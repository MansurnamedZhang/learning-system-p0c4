# P0-C2 Worker 运行边界

`learning-worker` 是内部服务进程。常驻入口为 `learning-worker --run`，默认每 500 ms 轮询，领取 30 秒租约；可显式使用 `--run --poll-ms 500 --lease-ms 30000`。它先转投未处理的 `job_outbox`，再扫描有界的到期/待领取任务，并通过数据库的原子领取函数取得租约。`--once --job-id <UUID> --lease-ms <N>` 仅供隔离验收和定向运维，领取不到任务时正常退出。

进程只接受以 `learning_runtime` 登录的数据库连接：`DATABASE_URL` 的解析后用户名、PostgreSQL `system_user` 保留的原始认证身份、`session_user` 和 `current_user` 都必须是该角色，且该角色不能是 superuser/BYPASSRLS。未认证、无法证明原始身份的连接会被拒绝；这项检查依赖 PostgreSQL 18。Worker 容器只注入运行角色的 `DATABASE_URL`，不要挂载或继承管理员、超级用户及测试数据库凭据；迁移由独立管理进程执行。日志不得写出数据库 URL、租约 token 或原始资产字节。`ASSET_ROOT` 和 `STAGING_ROOT` 必须是绝对路径。运行容器只需数据库内部网络，不开放主机端口；权威资产卷以只读方式挂载到 `ASSET_ROOT`，`STAGING_ROOT` 可使用独立临时卷。

Worker 在领取任务前要求 `ASSET_ROOT` 已是一个真实目录，不会把缺失的挂载点自动创建为空目录。数据库已有 ready 资产时，目录中还必须至少有一个形如 `sha256/<两位小写前缀>/<完整小写 SHA-256>` 的普通文件；隐藏文件、其他目录和软链接都不算。全新数据库尚无 ready 资产时，合法空卷可以启动。这是防止缺失或异常空挂载的启动预检，**不是卷身份或所有资产完整性认证**：若误挂载的卷含有符合格式但无关的文件，仍可能通过；单个资产缺失或损坏仍由作业处理器逐项判定。部署时必须将正确的权威卷绑定到该路径并监控挂载，非空误挂载残余风险记为 P2。

常驻模式的租约范围为 30–300 秒；处理期间每约三分之一租约时长续租。收到 SIGTERM/SIGINT 后不再领取新任务，允许当前处理完成后退出。强制终止的进程无法续租；数据库时钟判定到期后，另一个 Worker 可领取新的 token。已领取但取消、撤权或租约易主的任务由处理器和数据库 fencing 阻止发布结果。`KNOWWEAVE_WORKER_TEST_GATE_DIR` 只在 debug 构建中启用，是隔离进程验收的同步点；release 构建不响应它。

目前仅在全新隔离 Compose 项目验证，不代表已部署生产。验收项目须使用独立数据库、内部网络与卷，保存进程 PID/退出码、SQL 状态、源码哈希和原始日志。
