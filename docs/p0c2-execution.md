# P0-C2 执行与隔离验证说明

业务写入先创建精确块修订和 block_asset_use，再在同一事务中写 job_outbox。转投器把待转投事件变成稳定 job；Worker 可以重复扫描和转投，数据库唯一键保证同一业务键只得到一条任务。Worker 领取时数据库生成 token 与到期时间；处理器重新打开发起 actor 当前可见的资产、验证原字节，并在同一事务内按当前 token 写结果和成功状态。进程中断后，另一个 Worker 只在 PostgreSQL 时钟判定租约到期后接管；旧 token 不能再提交。

开发与隔离验证使用专用 Worker 服务，具体 Compose 配置、管理夹具命令和故障注入步骤见 [Worker 容器验收协议](../deploy/worker-acceptance.md)。先用唯一项目名和基础 Compose 启动全新 PostgreSQL、确认空库；无管理密钥的构建容器离线编译，再由独立管理容器建真实业务任务。拿到任务 ID 与导出的只读单文件二进制之后，才加载 Worker 叠加配置。专用 Worker 仅挂 runtime_password、只读权威资产卷、只读二进制和私有 tmpfs；绝不能复用持有 admin/postgres secret 的测试服务作为隔离证据。

Worker 入口支持单作业一次运行与轮询运行。一次模式用于精确作业及故障验收；持续模式接收停止信号后不再领取新任务，当前处理由租约续期或到期接管保护。无论模式如何，生产系统需要单独的凭据发放、进程监督、日志留存、时间同步、备份恢复和滚动升级设计，本阶段没有宣称生产可用。

隔离验收时保留源码包/清单 SHA、固定镜像、六空库、唯一网络和卷、容器实际 inspect、数据库时钟快照、进程 ID/信号/退出码、原始 stdout/stderr、四套冻结升级与全工作区日志。失败批次不得覆盖；修改验收运行器须使用新项目重跑。最终可核验结果和已知限制见 [C2 验证记录](p0c2-verification.md)。
