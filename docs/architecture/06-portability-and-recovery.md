# 06 快照交换与备份恢复

## 三种可移植产物

| 产物 | 目的 | 保存范围 | 不能代替 |
| --- | --- | --- | --- |
| 阅读副本 | 离线连续阅读 | 经裁剪的可读内容与允许的媒体 | 精确身份交换或灾难恢复 |
| C3 精确目录包 | 授权范围内迁移一个 Reading 固定闭包 | 必要对象、具体修订、关系与审查、可选原件 | 全库用户、授权、可变 head 和全部资产备份 |
| C4 全量备份 | 将一个实例恢复到干净目标 | 数据库一致快照、全部逻辑资产及字节、角色规则与构建/迁移身份 | 未验收的候选包不能作为已完成恢复许可 |

## C3 导出与交付

在一致的只读事务中固定 Reading 和必要引用闭包；规划、发布成功结果、每次交付都重新核对当前授权。私有 attempt 目录经流式核摘要、预算及 no-follow 检查后封存，不公开 staging 或失败中间件。

精确目录包用版本化 manifest 描述对象身份、内容摘要、文件清单与合同。metadata-only 导出保留授权资产元数据，不复制原件，也不消耗 included-originals 字节预算；实际包含的原件字节须受相应限额约束。

metadata-only 的目标原件核验属于导入预检及事务内复核：目标必须已有同 space、同 asset ID 的相同元数据与真实原件，并重新打开核对大小和摘要。仅有相同 digest 的另一资产不足以满足要求；导出不能证明目的地原件可用。

实际交换能力区分 `exact_import_v1` 与 `reading_copy_v1`。入口为普通目录，不接受任意压缩包解包导入。Linux 是权威 staging/交付验收环境，Windows 对这条权威文件链当前 fail closed；Windows 合同测试不能代替 Linux 文件安全门。

阅读副本去除不应暴露的精确身份，不冒充 exact。导出内容的历史版本固定，但读取授权仍是当前状态。已经交付的字节与句柄无法远程撤销。

## C3 导入的原子可见

1. 预检版本、文件路径、摘要、身份、引用闭包与资产可用性。
2. 核对并定稿原件字节，保留受控文件句柄。
3. 在数据库事务中重核授权、全部不可变字段、自然键和 registry 完整集合。
4. 固定顺序插入，初始化新容器的必要 head；已有 head、published 与 release 不后退。
5. 强制执行延迟约束后，将权威行与 `snapshot_import_batch` 回执一起提交。

同 ID 同字节可以复用，同 ID 不同内容拒绝。PreparedSnapshotImport 是已预检输入，不是绕过事务内权限复核的许可证。事务失败不出现半可见业务视图，但可能留下不可引用 CAS 字节。

C3 不创建 app_user、space 或 grant；缺失的第三方 reviewer 历史不能靠冒充用户导入。新容器 head 初始化是确定性的目标构造，**不是恢复源端全部可变 head**。因此 C3 不能被称为 C4 完整恢复。

exact 白名单固定为 29 张表，排除用户/空间/grant、普通回执、release/lineage、job/outbox 和导出结果。完整名单以格式文档为准，不通过本章概览推断额外表可导入。

## C4 全量备份链

管理协调器在受控写入维护窗中阻止新变更、排空必要在途操作，取得数据库一致 dump 和资产全量清单。包包含 `database.dump`、`roles.json`、`asset-index.json`、资产字节及版本化 manifest；没有当前引用的逻辑资产也须考虑，不能只沿一个 Reading 求闭包。

现有源端 API 要求可信管理调用方先停 runtime/Worker，再按写闸协议撤销 CONNECT、排空会话与封存；不能假定库函数会自动管理所有外部进程。只有 dump、index、control 持久化且本地 sealed pin 中全部原件验证完成后才重新开放 CONNECT，维护窗口可能较长。缩短窗口是待验证的后续优化，当前没有短时完成保证。操作与退出状态保留持久 journal。

构建身份、PostgreSQL 主版本、迁移版本和校验列表参与兼容性判断。资产目录按逻辑身份排序，文件按 digest 复用；逻辑资产数量、唯一字节量与文件数分别核对。

| 状态 | 已建立什么 | 尚未证明什么 |
| --- | --- | --- |
| Staging / BackupPlan | 规划和清单 | 原件已核完、dump 有效、传输完整 |
| SealedBackup | 私有包经摘要、路径和封存检查 | 已有独立故障域副本或实际可恢复 |
| CompleteBackup | 需要独立目标见证与受信校验链 | 当前单机验证不能签发或宣称此状态通过 |

目标见证与签名合同已有代码和专项，默认完整收据门受控关闭。只有 feature 并不足够，还需要受审构建的 verifier 信任绑定和实际独立目标验证。当前用户没有独立备份目标，单机传输通过仅证明该范围，不构成抗整机故障备份。

## 干净目标的信任链

恢复目标准入核对全新数据库、角色配方、权限、PG18 初始化事实与 Compose/卷身份。出生证明绑定受控创建事实；pin 候选记录固定目标观察。它们是后续恢复前提，不是任意输入 DSN 指向“差不多相同实例”就可以继续的依据。

当前只读绑定进一步核对精确容器、网络和挂载、PG system identifier/database OID、启动身份、会话与同一 SQLx 事务中的两把锁。只读子进程限定精确 Docker 目标和本地 Unix socket，不接受用户随意提供主机、端口或新的 passfile。

物理克隆负例验证：即使两个实例拥有相同 system identifier 和 database OID，错误端点仍必须拒绝。因此仅核对数据库“身份数字相同”不够。

同一 guard 重启负例验证：首次只读证明成功，目标重启后原会话被拒绝，旧 guard 不可复用，最终精确停机留卷。预期的 Session 拒绝是该负例成功条件，不是批次失败。
