## 状态用语

| 用语 | 含义 |
| --- | --- |
| 已隔离验收 | 指定源码、夹具、环境和阶段门已运行并保留证据，不代表生产就绪 |
| 部分专项通过 | 指定能力通过；不能外推为所在阶段全部通过 |
| 已实现但未整体验收 | 存在代码或契约，还缺实际环境或端到端验证 |
| 待建设 | 目标能力，不属于当前可交付应用功能 |
| 可选演进 | 真实需求、容量和测量支持后再决定是否接入 |

## 维护规则

这里是当前架构的阅读入口；具体接口以 Rust 类型、SQL 迁移和对应边界文档为准，具体验收以各阶段验证记录为准。历史设计和旧失败记录继续保留。发生冲突时核对日期、源码与证据，不能仅凭“更新更晚”推翻旧实验事实。

新增业务能力同时更新负责章节、决策记录、实现状态和证据链接。改变正文契约、目录包格式或数据库模式时分别升级版本，不以文档版本替代协议版本。图源和 SVG 放在 diagrams（私有或未公开参考），正文为可编辑 Markdown；HTML 是阅读副本。

没有新增服务、执行数据库迁移或修改运行数据。本次也没有清理编译缓存、测试卷或验收证据。

## 生成离线阅读版

图示 SVG/Mermaid 已随文档保存。使用 Node 与 `marked` 渲染，输出不依赖 CDN 或在线图形库：

```sh
node scripts/build_architecture.mjs
# 可选：将完整阅读版输出到指定目录
node scripts/build_architecture.mjs --output /path/to/KnowWeave架构设计.html
```

脚本先尝试当前 Node 环境的 `marked`，也可用 `KNOWWEAVE_DOCS_NODE_MODULES` 指定已有依赖目录；Codex Windows 环境支持只读复用随应用提供的依赖。它只读取架构正文与图示，不读取凭据或原始验收包。相邻 `.qa.json` 记录章节、链接和图示检查；它是文档生成检查，不是业务测试结果。
