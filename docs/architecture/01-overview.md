# 01 总体架构与产品边界

KnowWeave 面向个人长期学习。第一条产品路径以深度学习、模型与工程材料为例，让学习者在连续阅读中保存自己的笔记、猜想、来源和实践证据。课程只是输入。用户需要从已采用的版本回看当时的材料、自己的判断及后续如何变化。

## 当前能力与目标架构

| 层 | 审查基线 | 设计目标 |
| --- | --- | --- |
| 使用入口 | Rust 库、受限 Worker、管理及验收工具 | 私有 Web 工作台，经同源 HTTP API 使用 |
| 内容与思考 | 块与修订、固定发布、个人阅读与位置、关系与认识审查 | 复用现有内核，把版本、归属和冲突呈现给用户 |
| 权威存储 | PostgreSQL 保存结构化事实，私有文件库保存原件字节 | 延续两类权威职责，按实际容量演进 |
| 后台处理 | 持久任务、资产完整性与范围快照处理器 | 逐步增加确有使用价值的派生处理 |
| 可移植性 | C3 规定范围交换已通过隔离验收；C4 的 Task8 限定完成、Task9 现场待闭合 | 受控完整备份、真实独立存储与干净目标恢复 |
| 学习流程 | 已有内容、关系和证据表达能力 | P1-B 串起目标、任务、尝试、产物、验收和复盘 |

![当前内核和目标产品的系统分层](../diagrams/knowweave-overview.svg)

采用模块化单体。领域规则和事务由同一代码库维持，未来 HTTP 进程与已有 Worker 分开运行，管理与恢复采用独立身份和受控入口。浏览器只接触 API 提供的最小投影。库接口传入的 `Principal` 由 HTTP 适配层依据可信会话构造。B1 已在独立合成预览中验证固定修订、三种阅读投影和即时撤权。B2 验证了追加私有笔记、同请求回执和旧修订草稿保留。

## 权威数据

| 层 | 事实 | 生命周期 |
| --- | --- | --- |
| 原件 | 文件字节、资源版本、来源位置 | 私有字节不可变，业务身份及引用在 PG 登记 |
| 内容 | 语义块、结构化正文、版本及作者 | 稳定身份与修订分离，正文更新追加修订 |
| 组合 | 固定出现、组合、发布、阅读和个人层 | 固定依赖可回看；更新或移位产生新版本 |
| 学习与思考 | 关系、判断及所依据的版本；后续实践和验收记录 | 历史事实按当时条件保存，修改结论要有新的依据 |
| 派生 | 阅读文件、预览、搜索和图投影 | 按来源与处理器版本再生成，业务读权限仍由权威系统判断 |

先把同一份文档在不同设备上安全读出来，并让一条个人笔记能保存、冲突时能恢复。多人共同编辑、离线双向同步、任意代码执行及扩展搜索留待出现明确场景。产品试用与恢复安全分别取证；使用真实持久数据之前仍按既定恢复与权限门验收。[首用切片设计](07-product-interfaces.md) · [交付顺序](11-delivery-plan.md)
