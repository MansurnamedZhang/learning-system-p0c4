# 08 部署运维与架构演进

## 目标部署与当前环境

目标为私有单机 Linux + Docker Compose；HTTPS 是浏览器入口，数据库和资产卷位于内部网络/私有路径。当前 `deploy` 提供隔离测试配置与升级夹具，没有完整生产 Compose、登录服务或生产恢复手册。

![目标部署与存储边界](diagrams/knowweave-deployment.svg)

API、Worker 和管理工具可共用构建来源但采用不同运行职责与凭据。普通任务不能得到备份管理凭据。宿主 root/Docker daemon 是可信管理边界，不能把容器限制写成对宿主管理员的防护承诺。

## 程序与运行数据分开

以下为目标目录职责，不是可复制执行的安装命令：

```text
application/     固定发布程序与前端静态产物
postgres/        数据库专用持久卷
assets/          不可变原件与业务登记对应的字节
staging/         上传、导出和未完成尝试
derived/         可重建预览、抽取和索引
backups/         封存包及独立副本见证记录
secrets/         与角色对应的私有凭据
evidence/        隔离验收记录与哈希索引
```

开发源码、编译缓存和课程原件不混放为一个服务卷。Windows 当前源码与生成文档在 D 盘；后续部署位置应明确程序、镜像、数据库、原件和缓存各自落点，不能只检查源码目录。

## 可观测性与验收

当前证据关注固定源码/包哈希、工具版本、项目/数据库/卷、命令退出码、测试计数、日志摘要和清理状态。root 私有结果与人机终端回传要记录来源，不能将回传摘要称为直接读取的私有日志。

生产目标需补充 API 延迟与错误、连接池、作业排队/租约/尝试/失败、资产核验、备份年龄与独立副本、恢复演练、容量增长和升级状态。日志保存可追溯标识而不打印密码、完整 DSN、token 或锁随机值。

Worker 租约使用数据库时钟；跨进程和运维审计仍需正确时间同步。服务器时间偏差及生产配置属于后续必须复核的门槛，不能以记录时间看起来合理推断已解决。

## 发布、升级与回退

锁定依赖及构建来源，保留发布版本与迁移指纹；先在全新隔离项目运行适当旧版升级和故障门，再考虑生产变更。迁移追加，不修改已发布迁移字节。

应用回退、内容修订回退与数据库恢复是三种不同操作。切回旧阅读版本不会逆向删除新修订；回退程序需要数据库兼容性；恢复必须使用完成其独立验收的备份和干净目标。

## 保留与清理策略

优先处理可重编/可重建缓存，记录清理范围和前后占用。Docker 镜像与构建缓存有共享层，不能将显示大小简单相加。停机容器不一定无价值，引用它们的卷、构建来源和日志仍可能构成验收依据。

旧隔离项目清理前先保存资源清单、源码和关键证据索引，明确当前验收所需的固定镜像及 C4 卷。只按已确认 ID/路径操作，不使用全服务器无范围 prune。权威原件要检查已提交引用、备份保留集及恢复所需字节。

当前没有通用自动垃圾回收器。失败包和 C4 禁止复用卷的清理也不能变成重新认证或复用它们的手段。

## 演进路线

| 阶段 | 交付边界 | 当前状态 |
| --- | --- | --- |
| P0-A、B1/B2 | 块、固定组合、发布、个人阅读与位置 | 已隔离验收 |
| P0-B3/B4 | 关系、认识审查、谱系、授权图查询与影响分析 | 已隔离验收 |
| P0-C1/C2/C3 | 原件、持久任务、范围快照交换 | 已隔离验收 |
| P0-C4 | 完整备份、干净目标实际恢复与整关故障注入 | 实施中；只读绑定专项通过 |
| P1-A | 身份、HTTP、连续阅读与内容编辑工作台 | 待建设 |
| P1-B | 单元、计划、尝试、产物、验收、复习与首批资料 | 待建设 |
| P2 | 批量升级、位置迁移处理、第二领域与规则推荐 | 待建设 |
| P3 / 可选 | AI、解析、语义检索、S3 或 Neo4j 投影 | 需求与实测支持后选择 |

文档中“P2 契约问题”表示问题优先级，不自动意味着路线的 P2 阶段才修复；影响生产边界的问题必须在相关生产验收前处理。

## 扩展条件

Neo4j 只考虑可重建图投影，正文和授权权威仍在 PostgreSQL；出现真实深图瓶颈、查询表达维护收益和投影恢复证据后重新评估。S3/对象存储需证明私有交付、不可变字节、摘要核验和备份闭包不退化。

新增领域优先通过块、单元、规则和路线包表达，不把某一课程 ID 写死到内核。增加解析器要登记输入版本、处理器版本、失败语义和限额；增加执行器则单独建立资源、权限及副作用边界。首版无需先引入 Redis、Kafka、Kubernetes、向量数据库或微服务拆分。
