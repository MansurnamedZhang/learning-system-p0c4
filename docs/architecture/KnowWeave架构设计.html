01 总体架构与产品边界

系统定位

知织 KnowWeave 是面向个人长期学习的知识与实践系统。首个使用场景是已有实践经验的学习者，以每周 10–15 小时学习深度学习、大模型与工程；核心模型应能复用于系统工程、数学等领域。

用户需要的不只是资料目录，而是能保留内容版本、个人思考、来源、实践证据和变化依据的工作空间。系统应回答“当前学什么、为什么学、怎样算通过”，并在内容更新后保留原先学习与判断发生的条件。

目标为单人私有服务器实例，浏览器跨设备访问同一权威服务。多人实时共同编辑、组织管理、离线双向同步、任意 Notebook 自动执行不属于首版范围。

当前形态与目标形态

层面 当前 目标及阶段
业务内核 Rust 块、修订、组合、阅读、关系与审查 继续复用，不在前端重写领域规则
持久化 PostgreSQL 18、SQLx、私有原件文件存储 单机起步，按实测演进
后台处理 持久 Worker，资产完整性与 C3 快照任务 后续按需增加预览、OCR、索引处理器
可移植性 C3 范围快照交换已验收 C4 全量备份与恢复实施中
用户入口 库接口、受控测试和管理工具 P1-A 登录、HTTP API、浏览器内容工作台
学习产品 知识证据内核已具备 P1-B 任务、尝试、产物、验收、复习和计划

当前没有正式 HTTP 服务、登录界面或前端。测试工具能够调用内核，不等于用户已经能在浏览器中完成学习流程。

总体架构

推荐模块化单体：以同一代码库维护领域契约与事务规则，未来 API 和现有 Worker 分进程运行；管理与恢复工具采用独立权限和运行入口。crate 是代码边界，不是微服务。

浏览器经受保护 API 访问内容；API 提取可信用户身份后调用内核。数据库保存结构化事实，原件库保存文件字节；Worker 执行持久任务。搜索、图投影和 AI 只能消费授权后的事实，不能成为另一套可以随意修改的正文主库。

五层数据与权威来源

层 数据 权威位置 失效与更新方式
原件 PDF、PPTX、Notebook、代码、图片与媒体原字节 私有文件库；数据库登记身份与摘要 字节变更生成新资产，不覆盖旧原件
内容 知识、笔记、问题、想法、猜想等版本化正文 PostgreSQL 关系列与有类型 JSONB 单块新增不可变修订
组合 文档、固定发布、个人插入层、阅读视图 PostgreSQL 固定引用与位置 新组合/阅读修订，不静默跟随最新正文
学习与思考 关系、认识审查；后续计划、尝试与能力验收 PostgreSQL 中各自独立记录 判断固定依据；新证据产生新判断
派生 预览、抽取、OCR、检索片段与图投影 可重建缓存或索引 依来源版本和处理器版本重建

当前实现已覆盖前四层中的内容、关系与认识审查；完整学习任务模型和大部分派生处理器仍待建设。JSON、Markdown、HTML 是交换或阅读格式，不能同时成为与数据库自由双写的权威正文。

不变的架构原则

  1. 最小维护单位是可独立解释与引用的语义块，不按固定字符数机械切分。
  2. 稳定身份、正文修订、出现位置、发布版本、阅读快照分别保存。
  3. 原文与个人思考可连续展示，但归属、权限、位置和版本保持独立。
  4. 正文和必要引用闭包共同授权；历史存在不代表永久读取权。
  5. 用户操作、持久事件和权威回执在相应事务内一致提交。
  6. 文件系统与数据库不假设分布式原子事务；顺序设计和失败留痕承担一致性。
  7. 离线阅读副本、范围交换包和全量灾难恢复备份是不同能力。
  8. AI 建议和知识关系不直接变成学习能力“已通过”的事实。

容量与性能的边界

现有阶段验收证明指定行为、回滚和权限语义；不是完整应用吞吐量或生产容量证明。数据库选型的合成中样性能不能替代包含登录、HTTP、权限、文件与浏览器渲染的测量。部署容量应依真实资料、文件大小、引用密度和任务负载测定。

02 块与版本化领域模型

一切皆块的准确含义

可以独立阅读、修订、复用的知识、笔记、图片、想法、猜想与证据正文采用统一内容块体系。身份、权限、出现位置、任务、资产字节、回执和学习事实仍有独立模型；不是把所有数据库行强行塞成同一种块。

至少区分三种粒度：Block 是长期内容维护单位；LearningUnit 是未来学习目标、任务与验收组织单位；RetrievalChunk 是可重新切分的检索派生片段。后两者不能替代块的长期身份。

主要实体

实体 职责 版本或引用规则
Block / BlockRevision 稳定内容身份与不可变正文 改正文生成 revision；相同正文摘要不合并业务身份
Composition / CompositionRevision 组织有序块或嵌套组合 成员固定版本，嵌套组合不得成环
Occurrence 组合中某一次出现 同一块重复使用时分别定位；保留完整出现路径
Release 固定发布根与可复现依赖闭包 校验与发布原子提交；不等同于可变工作头
Overlay / OverlayRevision 属于个人的插入与编排层 固定原文基线，不直接修改原文
Placement / GapAnchor 个人块在原文间隙的位置 正文与移动分别修订；不依赖屏幕坐标定位
ReadingView / ReadingViewRevision 原文、个人层与所选关系的阅读版本 支持 Original、Fused、Personal 投影
Relation / RelationRevision 有类型、有方向的语义关系 端点固定具体块修订，关系自身也有修订
RelationReview / EpistemicReview 关系审查和认识判断 固定依据及适用条件，不由关系数量自动推断真伪
Lineage 派生、拆分与合并谱系 保存前后身份与引用，不冒用旧 ID
Asset / ResourceVersion / SourceSegment 文件身份、逻辑资源版本与来源定位 资产字节不可变；业务资产身份不同于内容摘要

数据库实体与 Rust 类型不是一对一映射。命令、查询投影、回执和精确引用也都是类型，但不应在架构图中画成独立服务。

正文形式与用途

intent 表示 knowledge、note、question、idea、conjecture、observation、evidence、conclusion。形式与用途分别表达；一段图片说明可以服务于笔记或证据，不需要制造另一套笔记文件系统。

当前已实现正文合同：

合同 已支持形式 尚不能推断的能力
v1 Markdown 文本与八类用途 不是整个系统的交换包 1.0
v2 文本、精确块引用、关系选择视图 不是任意自由 JSON 或任意对象 target
v3 在版本化正文体系中加入 Figure、Attachment 不等于独立公式、代码、表格、练习、评分规则类型全部实现

公式和代码可以作为文本内容展示；若需要结构化编辑、类型校验和专门执行语义，应追加自己的合同与验收，不能仅凭 Markdown 能显示就宣称已支持该业务类型。

身份与摘要

Block ID 代表“哪一个知识对象”，Revision ID 代表“这个对象的哪一版”，正文摘要用于核对规范内容字节。两个来源或归属不同的块即使正文相同也可拥有不同身份。

精确引用携带稳定 ID 与修订 ID。关系、关系审查和认识审查拥有各自的精确引用类型；依赖还标明 basis、target、requires_context、source_run、selected_relation、selected_review 等作用。禁止将未知字段或未登记引用藏在自由载荷中绕过授权。

可变 head 便于继续编辑；正式发布与阅读修订固定依赖，不能自动换成 head。正文、位置、关系、包格式和数据库迁移拥有不同版本维度，不能用一个“项目 v2”替代这些规则。

连续阅读与插入

原文 A @固定修订
  个人笔记 N @修订1
  个人图片 I @修订2
  猜想 H @修订1
原文 B @固定修订
  引用另一文档中的块 R @固定修订
原文 C @固定修订

间隙锚点固定原文组合修订、完整 occurrence 路径、左右邻居及附着偏好。文首、文尾和两块之间均可定位。页面的“连在一起”是阅读投影；不把个人块直接写入别人的源组合。

原文更新后保留旧基线，计算可迁移候选。映射不能确定时保留待重新放置项，用户仍可找回内容。自动保存、任意间隙插入控件、外观区分和迁移确认页面属于未来前端；当前已有对应阅读和位置内核。

猜想与知识修订的两条主线

“猜想—证据—反例—结论”通过有方向关系和条件化审查表达。猜想修订后，不自动继承旧版结论；证据撤权后，当前投影不泄露隐藏标识和路径。

“知识修订—影响范围”先创建新修订，再找出固定范围内的引用者、具体出现位置、关系及解释路径。结果用于选择采用新版的组合，不能自动改写已发布文档或历史事实。

支持/反对的知识判断已实现；“某学习任务是否通过、能力是否掌握”是 P1-B 待建设的另一套条件化验收，不可混淆。

实现依据

契约见 content.rs、content_version.rs、references.rs、overlay.rs、relation.rs。模式见 migrations；实际限制以合同类型与数据库约束为准。

03 Rust 模块与代码边界

实际代码结构

当前 workspace 是 Rust 2024 edition、Rust 1.97、锁定 Cargo.lock 的五个 crate；Tokio 提供异步运行，SQLx 访问 PostgreSQL 18，Serde 表达版本化 JSON。没有 Axum、React 或 HTTP 登录模块被当作已经实施的应用。

crates/
  learning-core/     领域契约、校验、精确引用与摘要
  learning-assets/   私有原件、安全文件操作、C3 目录包
  learning-db/       权限、事务、图查询、持久任务与原子导入
  learning-worker/   作业轮询、处理器、租约和进程停止
  learning-backup/   C4 清单、封存、收据、恢复预检与绑定
migrations/         0001–0015 追加模式迁移
deploy/             隔离 Compose、初始化、升级夹具
scripts/            受控验收与管理辅助脚本
docs/               设计、边界、实施及验证记录

未来 learning-api 与 apps/web 尚不存在于当前 workspace。部署测试夹具中的旧源码是升级输入，不是另一套正在维护的产品实现。

Cargo 依赖

模块 直接依赖本仓库模块 明确不承担
learning-core 无 不连接数据库、不处理登录、不持有文件权限
learning-assets core 不认证 actor，不独立决定业务读取权限
learning-db core、assets 不提供浏览器身份验证，不把 SQL 账号等同于用户
learning-worker core、assets、db 不决定学习是否掌握，不承担 API 或高权管理
learning-backup assets、db 不是普通用户导出，不是已完成的生产恢复入口

表中只列直接 Cargo 依赖；backup 可经 db 使用 core 的能力，不应画成不存在的直接依赖。模块共享契约，但原件 I/O、数据库授权与管理操作不能因为处在同一仓库而混用职责。

推荐读代码顺序

  1. 从 Cargo.toml 与各 crate 的 lib.rs 确认模块和公开入口。
  2. 阅读 core 的 content、composition、overlay、reading、references，理解身份、位置和固定版本。
  3. 阅读 db 的 write、release、reading、relation、impact，理解事务与当前授权。
  4. 阅读 assets 的资产存储及快照目录代码，再看 db 的 asset 和 snapshot 模块。
  5. 阅读 job 合同、0011–0014 迁移和 worker 处理器，理解 token fencing。
  6. 阅读 backup 的 restore_policy、restore_preflight 与 target_binding；再对照 db 的 snapshot/import，区分 C4 恢复与 C3 范围导入，同时核对各阶段状态和公开/内部边界。

示例和验收程序可说明调用方法，但不能替代生产身份边界。对当前内部接口进行 HTTP 包装前，要明确 trusted caller、actor、请求收据和错误投影的责任。

C4 当前代码包含文件清单、角色恢复规则和目标绑定，不因此产生“已完成 C4 数据库恢复”的事实。追加迁移和旧版升级须保持已发布迁移字节不变。

分层约束

纯合同检查靠 core，涉及可见性与原子提交的检查靠 db，实际文件句柄与字节靠 assets。Worker 协调这些能力；它不是授权规则的第二实现。高权备份与恢复不进入普通 Worker 的凭据范围。

数据库约束与延迟触发器负责持久不变量，Rust 入口负责命令校验和可读错误。参数化运行时 SQL 不能称为已经完成全部 SQL 的编译期校验。

代码事实来自 workspace 和 内容边界。每个阶段还有自己的 boundary、execution、verification 三类文档，分别回答“做了什么、怎么落地、怎样验证”。

04 事务授权与关系查询

用户身份与数据库角色

Principal 是可信调用方传入的业务 actor；当前内核不提供终端用户登录。未来 HTTP 层必须从已认证会话提取 actor，不能相信浏览器自行声明的作者或用户 ID。

空间授权决定 actor 对业务对象的读写权限。learning_runtime 是可信内部服务的数据库身份，非数据库 owner、非 BYPASSRLS；它不是每位最终用户的独立权限域。数据库账号不能交给浏览器，管理凭据不能交给普通 Worker。

当前 space_grant 有对应行表示可读，can_write=true 才能写。用户授权由 Store 检查，不能称为已实现用户级数据库 RLS。受限 SECURITY DEFINER 函数锁定 grant；runtime 不因此获得修改授权表的权限。

正文、引用端点、来源、位置、路径、审查依据及精确资产使用都参与授权。摘要一致、对象在旧快照中存在、UUID 难猜，都不能代替当前授权。

一次保存的事务边界

可信 actor + 命令 + request_id + base_revision
  → 合同校验与请求摘要
  → 幂等请求锁、当前授权锁、目标对象锁
  → 检查当前权限与基础修订
  → 新增不可变修订、依赖登记、工作头及业务回执
  → 若该业务需要后台处理，同事务追加持久事件
  → 提交后返回确定结果

幂等键范围包含 actor；同键同命令重放返回绑定结果，同键不同命令冲突。重放仍先检查当前写权限，不能利用旧收据在撤权后完成写操作。相同正文的新请求仍可以产生独立业务对象。

乐观并发检查基础修订。Conflict 表示工作头已经改变，不是自动覆盖许可。未来前端应保留未提交草稿和不确定请求，重试保留 request_id；收到服务器确认才显示已保存。

READ COMMITTED 下正文与当前权限在同一语句快照判断。需要跨多个对象验证与发布时使用明确锁序及事务；先得到必要 grant 锁的写入可使撤权等待，撤权先提交则后续操作拒绝。已经返回的内容无法被远程收回。

不泄露隐藏对象

读不存在与不可见对象采用一致的无结果语义；必要依赖不可读时按对应投影规则拒绝或裁剪，不返回隐藏 ID、路径或数量提示。游标依据可见结果生成，不能通过分页总量泄露隐藏数据。

隐藏对象碰撞须先沿真实目标归属授权，再决定能否报告 IdentityConflict。Storage 类错误不得向用户暴露 SQL、连接参数或完整 DSN。公开 HTTP 错误映射尚待 P1-A 定义和验收。

发布和固定闭包

发布固定组合与阅读输入，求出完整必要引用闭包，核对类型、精确修订、权限、环与上下文。通过后清单、发布记录和对应回执原子可见；失败不留下半发布。

正文引用、组合嵌套、思考关系、来源谱系和能力硬先修具有不同语义。组合嵌套必须无环；思考关系允许成环，但遍历必须有预算；未来能力硬先修需单独保证无环。不得把五种图合为一个不区分作用的边列表。

关系查询与影响范围

“猜想—支持/反对—审查依据”和“修订—消费者—出现位置—解释路径”在 PostgreSQL 权威表上查询。影响结果是待复查候选，不会自动改写已发布消费者或旧判断。

查询输入固定范围与版本；限定深度、扩展量、结果与超时。隐藏桥不能参与继续扩展；可见节点之间如果只通过不可见对象相连，不能泄露那条路径。预算耗尽、结果截断、没有结果和执行失败应分别表达。

图形 UI 可以直接使用 PostgreSQL 返回的授权投影，并不要求安装 Neo4j。若未来引入 Neo4j，正文回读仍由权威库重新授权，投影结果不能变成绕过权限的凭证。

已知限制

限制 含义与后续动作
内核 trusted caller P1-A 必须补登录、会话、HTTP 授权和错误投影
共享 runtime 能力 持当前 token 的内部代码仍可误用通用完成函数；生产前需收紧已记录契约缺口
文件已交付 撤权可以阻止后续交付，不能擦除用户已取得的字节
查询预算 有界查询支持可解释失败；不承诺任意密图都完整返回

依据：内容边界、B3 边界、B4 边界、C2 边界、C3 边界。

05 原件存储与持久任务

原格式、统一格式与派生格式

PDF、PPTX、DOCX、Notebook、代码与媒体保留原字节及格式；元数据和已编写的语义块采用统一合同。抽取文本、缩略图和检索片段是可重建派生物，不覆盖原件，也不成为笔记的唯一长期身份。

Resource 表示一份逻辑资料，ResourceVersion 固定内容与来源元数据，Asset 登记某份字节，SourceSegment 记录版本内定位。资产业务 ID 不等于内容哈希；文件可以按 SHA-256 复用物理字节，但不能跨授权边界合并逻辑身份。

当前 SourceSegment 保存固定资源版本内的 selector，尚无定位真实性验证或独立审查状态。后续来源定位入口应记录人工或可靠处理器的核对状态；未经核对不能推测页码、cell 或时间范围，也不能宣称 verified。这是后续产品规则，不是当前字段或验证器的能力。

原件写入与读取

受控输入
  → 私有 staging / 流式大小与摘要检查
  → 文件句柄与路径安全检查
  → 不可变原字节定稿
  → 数据库登记资产及精确使用关系
  → 事务提交后通过授权入口读取

文件系统与 PostgreSQL 不具有共同原子提交。失败可能留下不可引用的定稿字节，不能因本次数据库回滚就删除可能被其它资产共用的 digest。C3 原子导入也是先核对并持久化 CAS 字节，再提交业务事实和回执。

Linux 路径处理拒绝符号链接、越界和不受信目录，使用 no-follow 与受控文件句柄避免名称替换。大小、摘要、同名碰撞、部分写入和中断都必须验证；SIGKILL 与同步测试钩子不是物理掉电证明。

读取需核对 actor、当前空间授权，并按 AssetUseRef 校验精确块修订或资源版本的使用关系。已知 storage_key 或 digest 不能直接授权下载；未来 HTTPS 文件入口必须继承该语义。安全文件 I/O crate 本身不负责业务身份判断。

持久任务链路

C2 在 v3 图片或附件的真实写入事务中追加 job_outbox。只登记资产、只关联资源版本或重放旧请求收据，不自动产生同一事件。旧 outbox_event 只保存组合发布事件，与 C2 job_outbox 是两个协议。

转投器按稳定业务键将事件原子收敛为一条 job。Worker 领取、续租、写检查点和完成都通过数据库判断当前租约 token；过期后新 attempt 可以接管，旧 token 不能再提交结果。

当前最多三次尝试，使用数据库时钟、有限错误类别和退避。保证的是至少一次执行与副作用收敛，不是进程只执行一次；取消与终态不复活。

处理器职责与隔离

首个处理器复核原件大小/SHA-256 并写轻量元信息；完成前重新检查原业务 actor 和精确使用授权，再以当前 token 原子提交结果。缺件、损坏或撤权使任务失败或拒绝；不回滚已正确保存的用户正文。

Worker 专用容器只获得 runtime 凭据，资产和固定二进制只读；暂存区为私有可写区。配置 C3 时另挂载服务所有的私有可写 SNAPSHOT_ROOT，不取得管理凭据。容器采用非 root、只读根文件系统和私有临时区。宿主 root 与 Docker daemon 仍属于可信管理边界，容器验收不能证明它们无法读取进程凭据。

C3 快照任务使用独立 snapshot_queued、snapshot_running、snapshot_retry_wait 状态与扫描入口，防止旧 C2 Worker 误领新类型。尝试目录由 job 和 lease token 隔离；进程重启从持久结果与文件摘要重开，而非依赖原内存对象。

文件寿命与清理

数据 性质 清理原则
Rust target、测试编译输出 可重编缓存 确认没有占用和证据依赖后清理
staging、失败尝试目录 私有中间文件 按 job 状态和引用核对，不能按时间直接推断无用
derived、检索与图投影 可重建结果 保留来源和处理器版本，失效后重建
原件 CAS 字节 权威文件 核对全部已提交引用及备份保留集后回收
测试 evidence 验收依据 先归档索引、摘要和必要日志，保留失败与成功的对应关系
C4 隔离目标卷 隔离/脏/禁止复用状态 未明确批准清理前保留，绝不当作下一批恢复目标

当前没有自动 TTL collector、公开下载 URL 或完整解析器集。租约过期不等于目录到期，撤权不等于立即擦除磁盘字节。依据：C1 边界、C2 边界、C3 边界。

06 快照交换与备份恢复

三种可移植产物

产物 目的 保存范围 不能代替

C3 导出与交付

在一致的只读事务中固定 Reading 和必要引用闭包；规划、发布成功结果、每次交付都重新核对当前授权。私有 attempt 目录经流式核摘要、预算及 no-follow 检查后封存，不公开 staging 或失败中间件。

精确目录包用版本化 manifest 描述对象身份、内容摘要、文件清单与合同。metadata-only 导出保留授权资产元数据，不复制原件，也不消耗 included-originals 字节预算；实际包含的原件字节须受相应限额约束。

metadata-only 的目标原件核验属于导入预检及事务内复核：目标必须已有同 space、同 asset ID 的相同元数据与真实原件，并重新打开核对大小和摘要。仅有相同 digest 的另一资产不足以满足要求；导出不能证明目的地原件可用。

实际交换能力区分 exact_import_v1 与 reading_copy_v1。入口为普通目录，不接受任意压缩包解包导入。Linux 是权威 staging/交付验收环境，Windows 对这条权威文件链当前 fail closed；Windows 合同测试不能代替 Linux 文件安全门。

阅读副本去除不应暴露的精确身份，不冒充 exact。导出内容的历史版本固定，但读取授权仍是当前状态。已经交付的字节与句柄无法远程撤销。

C3 导入的原子可见

  1. 预检版本、文件路径、摘要、身份、引用闭包与资产可用性。
  2. 核对并定稿原件字节，保留受控文件句柄。
  3. 在数据库事务中重核授权、全部不可变字段、自然键和 registry 完整集合。
  4. 固定顺序插入，初始化新容器的必要 head；已有 head、published 与 release 不后退。
  5. 强制执行延迟约束后，将权威行与 snapshot_import_batch 回执一起提交。

同 ID 同字节可以复用，同 ID 不同内容拒绝。PreparedSnapshotImport 是已预检输入，不是绕过事务内权限复核的许可证。事务失败不出现半可见业务视图，但可能留下不可引用 CAS 字节。

C3 不创建 app_user、space 或 grant；缺失的第三方 reviewer 历史不能靠冒充用户导入。新容器 head 初始化是确定性的目标构造，不是恢复源端全部可变 head。因此 C3 不能被称为 C4 完整恢复。

exact 白名单固定为 29 张表，排除用户/空间/grant、普通回执、release/lineage、job/outbox 和导出结果。完整名单以格式文档为准，不通过本章概览推断额外表可导入。

C4 全量备份链

管理协调器在受控写入维护窗中阻止新变更、排空必要在途操作，取得数据库一致 dump 和资产全量清单。包包含 database.dump、roles.json、asset-index.json、资产字节及版本化 manifest；没有当前引用的逻辑资产也须考虑，不能只沿一个 Reading 求闭包。

现有源端 API 要求可信管理调用方先停 runtime/Worker，再按写闸协议撤销 CONNECT、排空会话与封存；不能假定库函数会自动管理所有外部进程。只有 dump、index、control 持久化且本地 sealed pin 中全部原件验证完成后才重新开放 CONNECT，维护窗口可能较长。缩短窗口是待验证的后续优化，当前没有短时完成保证。操作与退出状态保留持久 journal。

构建身份、PostgreSQL 主版本、迁移版本和校验列表参与兼容性判断。资产目录按逻辑身份排序，文件按 digest 复用；逻辑资产数量、唯一字节量与文件数分别核对。

SealedBackup 私有包经摘要、路径和封存检查 已有独立故障域副本或实际可恢复

干净目标的信任链

恢复目标准入核对全新数据库、角色配方、权限、PG18 初始化事实与 Compose/卷身份。出生证明绑定受控创建事实；pin 候选记录固定目标观察。它们是后续恢复前提，不是任意输入 DSN 指向“差不多相同实例”就可以继续的依据。

当前只读绑定进一步核对精确容器、网络和挂载、PG system identifier/database OID、启动身份、会话与同一 SQLx 事务中的两把锁。只读子进程限定精确 Docker 目标和本地 Unix socket，不接受用户随意提供主机、端口或新的 passfile。

物理克隆负例验证：即使两个实例拥有相同 system identifier 和 database OID，错误端点仍必须拒绝。因此仅核对数据库“身份数字相同”不够。

同一 guard 重启负例验证：首次只读证明成功，目标重启后原会话被拒绝，旧 guard 不可复用，最终精确停机留卷。预期的 Session 拒绝是该负例成功条件，不是批次失败。

恢复后的作业与失败隔离

恢复政策代码已区分终态、旧租约和未完成作业，实际执行与验证仍待整链验收。旧 token 不能在新目标继续完成，外部副作用不能因恢复而无条件重放。验证一致后再开放服务，派生物另行重建。

发生 ACL 变更、目标身份无法证明或恢复失败时，目标标为脏/不可用/禁止复用，按精确容器 ID 停机，保留卷与证据。不能用清理脚本把失败变成“干净目标”，也不能在同一失败批次重跑。

07 API 前端与学习闭环

本章状态

本章是已批准方向的后续产品设计整理，不是当前 API 文档。HTTP 路由、登录方案、DTO、前端依赖和完整学习表结构均需在相应阶段固化。Rust 后端已确定；Axum、React + TypeScript + Vite 是建议组合，尚未成为现有应用依赖。

API 的接入边界

浏览器只访问受保护 API，不连接数据库、不读取原件路径、不持有管理或 runtime 凭据。HTTP 层负责认证与会话失效、可信 actor 提取、输入限额、领域命令映射和可安全显示的错误；核心事务和授权继续由已验收内核执行。

API 类别 复用内核 还需验证
块编辑与历史 精确修订、请求摘要、冲突、幂等收据 身份不可伪造、限额、重试和草稿保留
连续阅读与个人层 Reading、Overlay、GapAnchor、迁移确认 三种投影、任意间隙插入、视觉归属、跨设备位置
关系与影响 关系版本、认识审查、有界图查询 HTTP 投影不泄露隐藏标识、路径、计数

快照导出与导入 C3 精确包、回执与 Worker 交付接口、大小与超时、不公开私有目录
管理与恢复 C4 管理合同 与普通用户入口分离，C4 验收前不开放写入口

目前没有冻结的 OpenAPI 文档或正式 endpoint 路径。命令示意不能直接用作已发布客户端合同。

前端信息架构

目标工作空间包含今日、学习路径、学习工作台、资料与知识、项目与证据、复盘与调整。P1-A 先实现内容工作台，P1-B 再连通完整学习流程。

连续阅读保持文档感：原文使用中性正文，个人笔记以侧线/标签和适度缩进区分；想法、猜想及待复核状态明确表达，不能只依赖颜色。图片沿其用途与归属呈现。关系面板、来源与版本在需要核对时展开，避免把数据库字段铺满正文。

插入个人块与编辑原文是不同模式。共享块编辑先显示影响；只想改变本处表达时派生新块，不静默覆盖所有消费者。原文升级先展示位置迁移候选与待处理项，旧阅读版本仍能打开。

前端状态与保存语义

服务端确认是“已保存”的依据；草稿和不确定请求留在前端缓冲。网络失败重试保留同一 request_id 和命令；冲突保留草稿与当前可见版本供对照，不自动回滚或覆盖用户输入。

跨设备访问的是同一服务器保存的阅读位置与业务状态，首版不建设离线双向同步。离线快照只是某一固定版本的阅读/交换产物，不能被解释为离线编辑后自动合并回权威库。

  → 阅读与实践 → 尝试 / 产物 / 观察

上述是目标模型，不是已经落表的 Rust 类型名称承诺。48 周路线是可复用内容模板；每周预算变化修订个人计划，不改写已完成事实。

能力分理解、实现、测量、迁移四个维度。阅读完成、自评、自动检查、AI 建议与人工复核分别记录；“通过”必须绑定任务、规则、内容和环境条件。换领域或换标准复用证据前检查兼容性。

AI 与外部实践

核心学习不依赖 AI。AI 可生成解释草稿、问题、关联或调整建议，必须保留来源和所用快照，并经明确操作采用；不能直接发布权威知识或改写能力判断。

Notebook 和代码默认在外部受控实践环境运行，系统记录原件、产物和条件。任意执行器、模型凭据、GPU 作业平台和恶意文件扫描需要独立设计，不能随上传功能自动开放。

08 部署运维与架构演进

目标部署与当前环境

目标为私有单机 Linux + Docker Compose；HTTPS 是浏览器入口，数据库和资产卷位于内部网络/私有路径。当前 deploy 提供隔离测试配置与升级夹具，没有完整生产 Compose、登录服务或生产恢复手册。

API、Worker 和管理工具可共用构建来源但采用不同运行职责与凭据。普通任务不能得到备份管理凭据。宿主 root/Docker daemon 是可信管理边界，不能把容器限制写成对宿主管理员的防护承诺。

程序与运行数据分开

以下为目标目录职责，不是可复制执行的安装命令：

application/     固定发布程序与前端静态产物
postgres/        数据库专用持久卷
assets/          不可变原件与业务登记对应的字节
staging/         上传、导出和未完成尝试
derived/         可重建预览、抽取和索引
backups/         封存包及独立副本见证记录
secrets/         与角色对应的私有凭据
evidence/        隔离验收记录与哈希索引

开发源码、编译缓存和课程原件不混放为一个服务卷。Windows 当前源码与生成文档在 D 盘；后续部署位置应明确程序、镜像、数据库、原件和缓存各自落点，不能只检查源码目录。

可观测性与验收

当前证据关注固定源码/包哈希、工具版本、项目/数据库/卷、命令退出码、测试计数、日志摘要和清理状态。root 私有结果与人机终端回传要记录来源，不能将回传摘要称为直接读取的私有日志。

生产目标需补充 API 延迟与错误、连接池、作业排队/租约/尝试/失败、资产核验、备份年龄与独立副本、恢复演练、容量增长和升级状态。日志保存可追溯标识而不打印密码、完整 DSN、token 或锁随机值。

Worker 租约使用数据库时钟；跨进程和运维审计仍需正确时间同步。服务器时间偏差及生产配置属于后续必须复核的门槛，不能以记录时间看起来合理推断已解决。

发布、升级与回退

锁定依赖及构建来源，保留发布版本与迁移指纹；先在全新隔离项目运行适当旧版升级和故障门，再考虑生产变更。迁移追加，不修改已发布迁移字节。

应用回退、内容修订回退与数据库恢复是三种不同操作。切回旧阅读版本不会逆向删除新修订；回退程序需要数据库兼容性；恢复必须使用完成其独立验收的备份和干净目标。

保留与清理策略

优先处理可重编/可重建缓存，记录清理范围和前后占用。Docker 镜像与构建缓存有共享层，不能将显示大小简单相加。停机容器不一定无价值，引用它们的卷、构建来源和日志仍可能构成验收依据。

旧隔离项目清理前先保存资源清单、源码和关键证据索引，明确当前验收所需的固定镜像及 C4 卷。只按已确认 ID/路径操作，不使用全服务器无范围 prune。权威原件要检查已提交引用、备份保留集及恢复所需字节。

当前没有通用自动垃圾回收器。失败包和 C4 禁止复用卷的清理也不能变成重新认证或复用它们的手段。

扩展条件

Neo4j 只考虑可重建图投影，正文和授权权威仍在 PostgreSQL；出现真实深图瓶颈、查询表达维护收益和投影恢复证据后重新评估。S3/对象存储需证明私有交付、不可变字节、摘要核验和备份闭包不退化。

新增领域优先通过块、单元、规则和路线包表达，不把某一课程 ID 写死到内核。增加解析器要登记输入版本、处理器版本、失败语义和限额；增加执行器则单独建立资源、权限及副作用边界。首版无需先引入 Redis、Kafka、Kubernetes、向量数据库或微服务拆分。

数据库实验的历史边界

早期 PostgreSQL/Neo4j 合成两场景基准支持首版技术顺序，但总合同为 NOT_PASSED：补充权限检查存在四项失败。后续 Rust 内核按正式权限合同完成对应阶段验收，不能反向改写旧实验为通过。

实验不能证明所有图查询都更快，也不能将进程内数据库调用时间当作完整产品延迟。后续引入 Neo4j 时须重新验证权限、同步、就绪、乱序、撤权与重建。
