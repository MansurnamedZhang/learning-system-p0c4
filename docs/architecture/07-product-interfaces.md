# 07 API 前端与学习闭环

本章是新的切片设计提案。Rust 后端与独立 Web 前端沿原批准方向。HTTP 框架、前端框架、URL 和身份方案由 P1 实施评审冻结。现有源码提供可复用的 Store 与命令。

## 首次使用 · 一篇可复现的 Attention 文档

1. 打开同一固定阅读修订。默认融合视图，能切换原文或个人层。笔记用归属标记区分，可展开块版本和来源。
2. 在两个出现点之一的间隙插入一条文本笔记，保留另一处的独立出现。使用 `GapAnchor` 和 `ReadingStore` 的版本与事务语义。
3. 服务端确认后刷新。手机与桌面看见同一固定修订和私有笔记。另一个主体不见笔记。
4. 模拟延迟或断开。客户端保留草稿，重试沿用原请求。遇到旧修订冲突时可打开当前允许的版本并保留手工合并内容。
5. 将文档升级与个人笔记迁移交互放在首切片之后。映射不确定的内容继续可找回，先由用户确认。

先使用合成文档与隔离数据库。第一阶段只读，第二阶段加入个人文本写。暂缓上传、全局搜索、共享内容批量编辑、AI 和学习计划。正式资料和持久发布按 [交付门](11-delivery-plan.md) 单列。

## HTTP 适配层设计

| 建议操作 | 复用能力 | 最小外部合同 |
| --- | --- | --- |
| 取一个固定阅读修订 | `ReadingStore::read_versioned` | 精确 view/revision、投影枚举和可见内容；含会话且避免共享缓存 |
| 取当前个人层及可编辑位置 | `ReadingStore::state` 与已有版本/位置模型 | 仅回传 actor 可用的版本、路径和位置；依当前权限判断 |
| 保存个人文本笔记 | `ReadingStore::edit` 及现有原子命令 | 请求 ID、预期基础修订、精确锚点、有限文本；返回确定的结果版本与保存状态 |
| 展开来源或已批准的媒体 | 资产及引用读取 Store | 经授权的逻辑使用引用；禁止浏览器拼路径或拿服务凭据 |

建议同源部署和服务端会话，HTTP 层验证会话、写请求来源和输入上限，依据会话映射 actor；浏览器可提交业务目标，无法指定运行身份。普通处理使用 least-privilege 数据库身份与允许的 Store。管理、备份、恢复与任何按任意路径操作的接口独立。

### 保存状态

| 观察到的结果 | 前端行为 |
| --- | --- |
| 请求未发出 | 草稿可继续编辑 |
| 等待或响应丢失 | 保留已发送的请求体、原 request ID 与草稿；按同操作重新确认 |
| 服务端确认 | 显示已保存和新版本；重试不产生第二次逻辑写入 |
| 冲突 | 保留草稿，提示比较允许看到的最新修订；确认再构造新命令 |
| 无权限或会话失效 | 终止当前命令、清除相应服务端结果缓存，按会话策略重新认证 |

不可见和不存在采用相同外部形状。未认证、校验失败、冲突、暂时不可用与成功分别可观察。响应不含 SQL、主机路径、隐藏关系或权限猜测信息。对 Markdown 按白名单处理输出，外链与媒体权限另审。桌面和窄屏都验证焦点、键盘操作、保存反馈和越权负例。

## P1-B 的最小学习数据

先用一次 Attention 实践建立事实链。学习单元固定目标、先修、资源版本和通过规则；用户在外部完成实现或测量并提交产物引用；验收记录所用规则、证据、评价者与条件，复盘与下次建议引用当时事实。计划调整追加版本。业务类型和数据库表由后续契约审定。

| 事实 | 首个可验实例 |
| --- | --- |
| LearningUnit / Plan | 一个因果 Attention 单元，绑定已发布资源与本周时间预算 |
| Attempt / Artifact | 用户实现及最小输入、环境标识、实际输出 |
| Assessment | 遮罩与形状校验、结果与失败原因，可回看当时规则 |
| Reflection | 卡点和下一步，无 AI 也可完成闭环 |

能力验收按理解、实现、测量或迁移分别记录。AI 可生成可追溯的建议，不替代事实和人工采用。实际写入学习事实前，先补相应迁移、授权、备份闭包和恢复用例。[事务授权](04-transactions-and-permissions.md) · [阶段验收](11-delivery-plan.md)
