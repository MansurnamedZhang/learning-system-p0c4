# P0-B4 code map (read-only inventory)

Source snapshot: `隔离工作树` at `4252cc812b6c3bb7e7fabbcc309522b005f9df44`, clean at inspection. This is a source map for the B4 plan, not an implementation or a claim of B4 verification. Line references below are relative to that worktree unless marked `roadmap`.

## Contract to map

Roadmap §6 requires exact starting revision, selected view/publication scope, allowed edge families, depth/return/work limits, visible explanation paths, deduplicated consumers plus each occurrence path, and complete/truncated/budget status. The required order is reverse-index audit → direct consumers → local evidence → impact traversal and unified output. It explicitly prohibits expanding a dense graph before applying the budget and treating budget exhaustion as no impact. [roadmap `docs/superpowers/plans/2026-09-19-p0b-content-assembly-roadmap.md:141-156`]

## Current trusted read surfaces

`Principal` supplies actor identity; reads use `request::begin_read` (`REPEATABLE READ READ ONLY`, 15-second statement timeout). Writes use `READ COMMITTED`, so a B4 multi-step query should remain in one read transaction for one snapshot. [`crates/learning-core/src/identity.rs:4`, `crates/learning-db/src/request.rs:6-40`] `authorization::lock_grants` is for mutation transactions; it returns `NotFound` on missing/insufficient grant. [`crates/learning-db/src/authorization.rs:6-27`]

`references::Session` is private to learning-db, caching *metadata* per operation and authorizing necessary dependency closure before materialization. Its budgets are 2,048 objects, 4,096 edges, 8 MiB, depth 32 and 131,072 work steps; exhaustion is `reference_budget_exceeded`. `object` returns `None` for hidden/nonexistent closure; it redacts an inaccessible previous revision. `directly_visible` distinguishes hidden root from visible root with hidden dependencies so reviews can yield `Unavailable` or `Incomplete`. [`crates/learning-db/src/references/closure.rs:10-35`, `:70-125`, `:189-217`; `crates/learning-db/src/references/mod.rs:10-18`] Registry lookup checks current `space_grant` and personal overlay ownership before reading dependencies. [`crates/learning-db/src/references/index.rs:20-64`] These closure budgets govern authorization payloads; they do **not** bound B4 reverse-candidate scans, queue/frontier size, path multiplicity or SQL rows.

Existing public Rust APIs are point or selected reads: `CompositionStore::read_versioned` fully authorizes a fixed composition closure; `ReleaseStore::state`, `read`, `active`, `read_evidence` expose root-scoped publication or release data; `ReadingStore::read_versioned` loads a fixed view and produces original/fused/personal projections; `RelationStore::read`, `read_selected`, `read_review`, `ReviewStore::read`, `group_sources`, and `LineageStore::read` project particular immutable references or operations. [`crates/learning-db/src/composition/read.rs:5-32`; `crates/learning-db/src/release/read.rs:39-131`; `crates/learning-db/src/release/evidence_read.rs:5-70`; `crates/learning-db/src/reading/read.rs:31-66`; `crates/learning-db/src/relations/read.rs:7-62`; `crates/learning-db/src/reviews/read.rs:7-69`; `crates/learning-db/src/lineage/read.rs:7-47`]

The reading DTO contains `Original { path, revision }` and a separate personal item `placement_id`/location; projection walks ordered occurrence nodes and appends each occurrence ID to its path. It orders groups by `(affinity,group_id)` and placements by saved group position, preserving repeated occurrences. [`crates/learning-core/src/reading.rs:69-102`; `crates/learning-db/src/reading/projection.rs:58-67`, `:69-127`] Reading selections project only authorized relation/review facts; inaccessible epistemic selections are omitted or marked incomplete. [`crates/learning-db/src/reading/selection.rs:73-116`] Relation and epistemic review DTOs already model `Available`, `Incomplete`, `Unavailable`. [`crates/learning-core/src/relation.rs:71-77`]

## Narrow candidate entry points and genuine gaps

1. **Direct fixed consumers:** begin at exact block revision via `occurrence_block_target`, then follow exact child composition revision parents via `occurrence_composition_target`, within a caller-chosen root revision or release. `composition::closure::load_with_session` already validates whole structure and counts each expanded occurrence, but its `Closure` maps distinct revisions, so path enumeration must preserve occurrence multiplicity. [`crates/learning-db/src/composition/closure.rs:8-35`, `:119-154`] A direct `release_root` hit only identifies a root; it cannot stand in for nested paths.
2. **Local evidence:** reverse `reference_dependency_target` can find v2 content basis/target/context and relation or review sources. Fixed view selections live in `reading_*_selection`; relation endpoints and review basis are available through the point-read APIs. A B4 evidence query API, edge-family policy, source-version selection and scope membership check are absent. [`migrations/0004_relations_review.sql:14-25`, `:280-305`; `migrations/0005_reading_evidence.sql:10-24`]
3. **Impact:** the only graph walk now is forward necessary-dependency authorization (`Session`) and composition closure loading. `crates/learning-core/src/impact.rs`, `crates/learning-db/src/queries/`, and a B4 shared projection module do not exist in the inspected tree; `learning-db/src/lib.rs:1-24` exports no consumer/evidence/impact store. No response type currently carries actual scope, visible paths, distinct consumers, occurrence paths, or complete/truncated/budget status.

## Planning cautions from the source

- **Privacy:** authorization must precede observable counts, pagination, edge expansion and paths. `reference_dependency`, release manifests, raw JSONB and `system_lineage` are internal facts. Hidden source or intermediate nodes may not bridge to visible descendants. Existing revocation tests exercise structured refs, relation reads/reviews and reading evidence, but do not establish B4 path/count safety. [`crates/learning-db/tests/reference_authorization.rs:5-18`; `crates/learning-db/tests/relations.rs:243-323`; `crates/learning-db/tests/reading_evidence.rs:170-215`; roadmap §3.4 `:95-108`]
- **Ordering and identity:** `position` orders siblings in a fixed composition revision, while full occurrence path distinguishes two appearances of the same child or block. A stable SQL page order must include tie-breakers after authorization. De-duplicate *consumer identity* separately from positions and explanation paths. [`migrations/0002_composition_release.sql:34-44`; `crates/learning-db/src/reading/projection.rs:83-127`; roadmap §6 `:152-156`]
- **Work limits:** current `Session` limits necessary closure size only. B4 needs independent limits applied to candidate rows, frontier pushes, checked edges, path count, depth and output, before `fetch_all` or unrestricted recursive CTE expansion; report exhaustion explicitly. A query timeout is a final guard, not a completeness signal. [`crates/learning-db/src/references/closure.rs:10-16`, `:90-125`; `crates/learning-db/src/request.rs:29-39`; roadmap §6 `:152-156`]
- **SQL performance:** indexed lookup exists for one exact dependency target and immediate composition targets. Existing PKs are source/scope-first for selections, placements and manifests. Endpoint, lineage and root-qualified reverse paths need measured query plans against dense fixtures; avoid asserting adequacy from schema alone. B4 acceptance specifically calls for actual server `EXPLAIN`/timing evidence. [`migrations/0002_composition_release.sql:71-75`; `migrations/0004_relations_review.sql:25`, `:117-119`; `migrations/0006_lineage.sql:22-36`; roadmap §6 `:156`]
