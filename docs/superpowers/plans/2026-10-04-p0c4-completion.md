# P0-C4 Remaining Completion Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Complete management-only backup/recovery code and fresh single-host full-chain acceptance now, then close the genuine independent-domain gate when a destination exists.

**Architecture:** Add independently provisioned storage enrollment/protection outside the business DB; reuse the accepted source lifecycle and explicit controlled-import supervisor. Admit full-schema SQL through a same-build PG18 contract and bounded COPY spool, then verify all rows/assets and normalize leases under isolation. Keep normal CompleteBackup authority distinct from the private single-host rehearsal.

**Tech Stack:** Rust 1.97, SQLx 0.8.6, PostgreSQL 18.6, Linux no-follow directory handles, Tokio, existing SHA-256/P-256 and Docker isolation helpers; offline Python acceptance adapters.

**Spec:** [completion design](../specs/2026-10-04-p0c4-completion-design.md), especially normative Appendix A and source-loss Appendix B, subordinate to the approved [parent design](../specs/2026-09-28-p0c4-backup-recovery-design.md) and accepted lifecycle/controlled-import subcontracts. Adopted 2026-10-05. Tasks 1-8 cover code and fresh single-host acceptance. Task 9 remains dependent on a genuine independent destination; parent C4 final closure is not claimed by plan adoption.

## Global Constraints

- Preserve old migration bytes, old source/build/control binding, source journal v1 canonical bytes, C1–C3 public contracts and fail-closed terminal ambiguity.
- No independent destination exists now. Do not operationally enable `independent-verifier` with a pretend off-host key, create CompleteBackup from a sealed pin, or claim `P0_C4_VERIFIED` before the external gate.
- No new business migrations; new registry, protection and recovery records live in management-owned storage.
- Normal restore accepts only CompleteBackup. Local full-chain capability is `#[cfg(test)]`, privately constructed from a fresh capture, has no caller bypass flag, and always quarantines the exact target.
- Every remote case uses fresh canonical UUIDs, source/build/PG volumes, exact source/build inputs and an unused subnet on `<test-server>`. Never reuse/replay old fixtures, failed targets or historical test credit.
- Fixed offline builder: `sha256:fb91f085b6002b8f75570993722a762579ad392e15c390e8161ffb746c858b9b`; PG18.6: `sha256:9e73daeb439141c2b11eea2463f5f1a3b269fd90d897b41cddb7cb440f21aa5d`.
- Management records private 0700/0600; secrets remain in human-terminal/provisioner private files, never code, package, logs, evidence, argv or full DSNs.
- Reconcile remains dry-run. Unknown/corrupt/stale storage authority withholds all candidates and blocks publication; no destructive GC is added.
- Registry locks are `LOCK_EX | LOCK_NB`; contention immediately returns `BackupError::Invalid("registry busy")`, with no synchronous retry/wait in Tokio. Metadata/protection scans share a 536870912-byte operation budget and max 100000 unique digest keys across DB/backup union; overflow returns no partial report or release/publication authority.
- New managers require independent enrollment before any mutation. Original archived manager+binding remain unchanged for old attempts; current focused fixtures are independently provisioned/rebuilt, never given an undocumented legacy bypass. The old controlled fixture is one probe table/two rows; old execution credit does not transfer.
- Global count limits: 100,000 logical assets, 64 MiB canonical asset index. New full-import and registry caps are specified in completion design and must fail explicitly, never truncate or widen silently.
- User already selected task-by-task implementation and independent review, waived routine per-step/per-package confirmation, and authorized normal feature-branch publication. Root owns dispatch, execution evidence and final Git operations. Each task below has one independent review gate.

## Review Focus

- Same-byte replacement of asset/pin/registry roots after restart must fail before ACL release or cleanup reporting (Task 1 tests).
- Correct DB name/OID/system ID on a physical clone must not admit a source dump (Task 2 tests).
- COPY data containing psql/SQL-looking bytes and an archive with a changed function/ACL must never gain executable authority (Task 4 tests).
- Commit-intent or recovery-receipt uncertainty after caller cancellation must remain unreplayable/unusable, even if DB bytes committed (Tasks 5–6 tests).
- Nonexpired old leases, missing snapshot export bytes and unrelated unreferenced/historical rows must survive/normalize without blind side-effect replay (Tasks 6–7 tests).
