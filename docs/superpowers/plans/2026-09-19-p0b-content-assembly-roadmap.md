## Global Constraints

- “稳定身份与内容修订分开。”
- “组合只保存引用、结构和局部展示信息。”
- “同一幂等键与同一请求内容重试返回原结果；同键不同内容拒绝。”
- “原文、笔记、图片、想法和猜想连续呈现，个人插入层独立保存。”
- “首版不常驻 Neo4j。”
- “不可见对象与不存在对象采用相同外部行为。”
- 不修改 P0-A 已执行迁移；新增迁移必须同时验证空库与从 P0-A 升级。
- HTTP、登录、前端属于 P1-A；图片字节、任务消费、文件导出与恢复属于 P0-C；批量升级体验属于 P2。

## 1. 本阶段要贯通的真实过程

下面是业务验收夹具，不是对 Attention 或大模型效果的科学结论。

1. 建立知识块 K（因果约束）与 M（实现说明），文档 A、B 均固定引用 K@1；A 内额外重复出现 K@1。
2. 在 A 的第一次 K 与 M 之间放笔记 N、想法 I，再在 N 与 I 之间放猜想 H。另一处 K、文档 B 不出现这些个人内容。
3. 建立 E1、E2、X：前两项是同一来源运行的观察，X 为反例；分别创建支持、支持、反对 H@1 的关系。
4. 保存对 H@1、指定关系修订与证据修订的人工条件化审查，再生成结论 C。来源运行分组只是相关性提示，不表示统计独立。
5. K@1 修订为 K@2；查询固定引用者及建议复查项。只发布 A 的新版，B 保持 K@1。
6. A 的结构变化产生个人层迁移候选；确认后生成新个人层和阅读视图。无法确定的位置进入待放置集合，旧视图可读。
7. H@2 不自动继承 H@1 的证据关系或认识判断；另行接纳关系或审查会产生新记录。
8. 撤销对 E1 所在空间的读取权限，再读 C、H 的关系和影响结果，验证所有结构化输出均不暴露 E1 的 ID、正文、路径或数量。

## 3. 边界选择及理由

### 3.1 组合引用和个人位置

- 组合每个 occurrence 指向确切块修订或确切子组合修订。显示“有新版”不更新引用。
- 同一个组合内重排保留 occurrence ID；复制一处生成新 ID。更换为不同稳定块也生成新 ID，不能利用位置身份偷偷替换含义。
- 嵌套位置是从根出发的完整 occurrence 路径；子组合重复嵌入时，路径不同。
- 个人 placement 独立有身份，只引用正文，不保存 note.body。
- GapAnchor 固定根组合及基线修订、父路径、左右邻居与 after_left/before_right。组内按 placement 有序列表插入，避免浮点序号耗尽或冲突。
- 选择“独立个人层”作为默认学习模式；直接编辑原组合只用于明确的原文编辑操作；派生专题组合用于重新组织材料。

### 3.2 升级和迁移

- 先保存知识新修订，再选择组合升级；升级个人层是另一项带基础版本的明确操作。
- 两侧邻居仍相邻且父路径一致：精确迁移仍写记录。
- 新增原文、仅剩单侧或发生跨章节移动：保存候选及原因，等待明确采纳；affinity 决定建议而非静默授权。
- 删除两侧、拆分/合并或无法唯一匹配：保存待放置项，保留旧锚点和可见旧上下文。
- 同组个人块整体迁移，内部顺序不变。用户拒绝候选后可留旧基线，或明确选择新基线并保留待放置项。
- 拆分至少创建两个新稳定块 ID，并由拆分操作追加只读谱系；不能把一个旧 ID 的连续版本伪装成两个新块。

### 3.3 关系、引用与结论

- 块链接、引用卡、语义关系和位置关系分开。相邻不是支持，支持不是证明，支持关系不传递。
- RelationRevision 固定两端 block_id/revision_id；关系改动不重写端点正文。审查记录独立追加，不修改关系修订。
- related_to 采用标准端点顺序，避免同一适用范围内正反重复；有向关系只存一个方向。
- 首批用户关系为 annotates/questions/answers/inspired_by/supports/opposes/tests/related_to。derived_from、split_from、merged_from 只由对应内容操作产生。
- EpistemicReview 固定猜想或结论修订、关系修订列表、证据版本、条件、判断人及时间；状态沿用已批准枚举，不按链接数自动产生。
- B3 为 basis_refs、target、requires_context 引入严格版本化契约。旧 content-v1 原字节摘要不变、仍拒绝这些字段；新增契约不能靠给旧 struct 加 optional 字段而悄悄改变旧摘要。
- relation_view 的动态查询仅属于工作态；保存 ReadingViewRevision 时解析成固定关系修订清单。
- 块引用卡内嵌最多两层，遇环转回跳链接；组合结构环必须拒绝，语义关系图允许环。

### 3.4 权限与展示

授权对象是空间中的事实，读取时检查当前授权。引用者可见不等于目标可见，历史发布不授予永久访问权。

| 输出 | 规则 |
|---|---|
| 组合原始结构与发布清单 | B1 保守采用完整闭包授权；任一必要引用不可读则整个读取不可用，避免泄露节点数和路径 |
| 个人层与融合内容 | B2 提供专门 DTO；保留可读个人正文，过滤不可见目标定位；不可定位内容返回个人待放置集合 |
| 结论 basis_refs、引用卡 target | B3 按字段投影，不向上层直接序列化权威 JSON；隐藏与不存在目标使用同一外部语义 |
| 支持/反对与反向链接 | 只返回关系自身及必要端点均可见的项；计数、分页基于过滤后的集合 |
| 认识审查 | 依据不再完整可读时，不把历史判断展示为当前已完整核对；不暴露缺失对象 ID 或数量 |
| 影响路径 | 不穿过隐藏中间节点，不返回可据此推断隐藏消费者的计数或路径 |

隐藏过滤针对系统管理的结构化引用；不会宣称可以从用户自由文本中识别并删除过去手工抄录的内容。原始内部记录不作为未来 HTTP DTO。

## 5. B3 的任务边界与验收合同

实现次序：内容契约版本兼容 → 严格引用及索引 → 关系保存与审查 → 认识审查 → 派生/拆分谱系。

预期文件责任：

- `crates/learning-core/src/references.rs`、`relation.rs`、`epistemic.rs`：类型化引用、关系与审查。
- `crates/learning-core/src/content_version.rs`：新旧契约分派，保持 v1 摘要。
- `crates/learning-db/src/relations/`、`src/reviews/`、`src/lineage/`：各自写入、授权读取与不可变历史。
- 新增顺序迁移与 `tests/relations.rs`、`tests/epistemic.rs`、`tests/reference_authorization.rs`、`tests/lineage.rs`。

必须钉住的接口字段：精确端点；关系类型、理由、条件、适用空间/个人层；基础关系修订；请求键；审查目标版本及固定依据；谱系操作输入/输出。客户端不能通过普通关系命令伪造系统谱系或 reviewer 身份。

验收集：猜想更新不带走旧关系；relation review 更新不改正文；撤回保留旧快照；对称去重在并发下仍成立；同源 E1/E2 只分组不推断独立性；隐藏证据不能从 basis_refs、target、正文回读 helper、关系路径、审查结果或计数泄露；隐藏与不存在行为一致；旧 content-v1 样例与摘要不变；新版本引用闭包缺失拒绝发布；split 创建不同稳定身份且旧版可读；内嵌引用深度和环有界。

## 6. B4 的任务边界与验收合同

实现次序：反向索引来源核对 → 直接引用者 → 证据局部查询 → 影响遍历与统一输出。

预期文件责任：

- `crates/learning-core/src/impact.rs`：查询范围、预算、解释路径及完整性状态。
- `crates/learning-db/src/queries/{consumers,evidence,impact}.rs`：按业务问题查询。
- `crates/learning-db/src/projection/`：共享授权投影规则，禁止绕过投影直接返回 JSONB。
- `tests/impact.rs`、`tests/projection_authorization.rs`、`tests/attention_flow.rs`。

查询必须携带：起点精确修订、所选视图/发布范围、允许的边族、深度上限、返回上限、服务端工作预算。响应携带：实际范围、可见解释路径、去重消费者及各 occurrence 路径、完整/截断/预算超限状态。不能把预算超限解释为“没有影响”。

结构引用输出“引用此旧版，采用新版需生成新组合”；语义关系输出“建议复查”，不推断真假或自动撤销学习事实。P1-B 的学习记录尚不存在，B4 不预造学习验收模块。

验收集：两条路径到同一消费者只计一个消费者但保留两个位置；菱形、语义环、深链、稠密可见邻居均受预算控制；权限过滤先于统计、分页和遍历；隐藏桥接点不连出另一端；被撤权缓存不能继续返回旧结果；固定范围重放结果确定；同一视图含旧/新块版本时结果不混淆；服务端真实查询计划与耗时记录，不以旧图实验性能代替本阶段证据。
