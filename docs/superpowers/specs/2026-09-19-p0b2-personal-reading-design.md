# P0-B2 个人插入层与固定阅读视图设计

2026-09-19 · `IMPLEMENTED / P0_B2_VERIFIED` · 用户在书面设计交付后要求“继续”，随后要求“推进吧”。B2 已完成独立审查与最终验收，宿主和全新 Compose 各 105 项通过。[B2 施工单](../plans/2026-09-19-p0b2-personal-reading.md)记录执行状态。

依据：[总体设计](../../学习系统设计方案.md)、[连续阅读设计](../../连续阅读与思考块设计.md)、[P0-B 总单](../plans/2026-09-19-p0b-content-assembly-roadmap.md)、[B1 实际边界](../../p0b1-boundary.md)。本文件细化 B2，不替代后续施工单。

## 1. 已确认目标与范围

个人阅读同一份材料时，可以在原文之间、个人内容之间插入笔记、问题、想法或猜想。插入只属于所选位置；同一知识块的其它出现处不会自动带上笔记。原文升级时，旧阅读版本保持固定，个人内容可迁移或保留待放置。

用户已明确确认：

- 一个个人层绑定一个稳定根文档 composition_id，可在该文档不同修订之间显式迁移；跨文档整理使用专题组合。
- 从融合阅读保存个人正文时，在同一事务产生块新修订、个人层新修订及阅读视图新修订；旧视图继续引用旧版正文。没有正文变化的移动或重排不产生块修订。

延续既有批准范围：Rust 内核 + PostgreSQL，新增迁移，不修改 0001/0002；现有 content-v1、B1 接口和原测试保持兼容。本关支持现有 text 的全部 intent。图片原件与 figure 在 P0-C，关系及其固定清单在 B3，HTTP/前端在 P1-A；本关交付可供前端使用的读取契约和事务能力。

## 2. 方案选择

| 方案 | 保存和复现方式 | 取舍 |
|---|---|---|
| 每次有效保存生成固定版本（采用） | 块、个人层、阅读视图在一笔事务中更新 | 历史直接可读，版本较多；正文独立存储，层只保存引用 |
| 工作态动态引用最新版，显式快照时固定 | 阅读时临时解析块头 | 写入较少，但普通保存历史不能直接复现，和已确认行为不符 |
| 只保存操作日志并重放视图 | 通过插入/移动事件还原状态 | 便于协同操作追踪，但增加重放、压缩和迁移成本，暂不采用 |

层修订保存完整的有序引用集合，读取不依赖重放全部历史。B2 采用层级乐观并发：同一基础层上的两个修改只能一个成功，即便修改不同间隙。自动合并和实时协同以后另行设计。

## 3. 权威对象和身份

| 对象 | 身份与内容 |
|---|---|
| Overlay | 稳定 overlay_id、owner_id、个人空间、固定根 composition_id、当前修订头 |
| OverlayRevision | 不可变修订；精确 base_composition、父修订、间隙组、待放置组、作者、理由、时间 |
| GapGroup | 稳定 group_id、一个 GapAnchor、有序 placement 集合；同组整体迁移 |
| Placement | 稳定 placement_id、精确 BlockRef；表示一次个人出现，正文不内嵌 |
| ReadingView | 每个个人层一个稳定 view_id 和当前修订头 |
| ReadingViewRevision | 固定个人层修订和相同的原文基线，作者与时间；每次有效保存追加 |
| PlacementMigration | 不可变迁移提案与独立追加的决定记录；固定旧层、新原文、分组结果和实际采用情况 |

同一根可以有多个个人层，创建时显式命名；B2 一份阅读视图只选一个层，暂不叠加多层。个人层访问要求当前调用者等于 owner 且仍有个人空间相应权限；仅有原文空间权限不能读取个人层。

Placement 在同一层各版本之间保持身份；不能借用另一层的 ID，不能把已移除 ID 重新作为新出现复活。引用同一块两次产生不同 placement。更换为不同稳定块必须生成新 placement；采用同一块新修订可保留身份。

每个组有独立身份，以便迁移留痕。一个个人层修订内，同一原文间隙和相同 affinity 最多一个已放置组。不同 affinity 的组可处于同一间隙，展示顺序固定为 after_left 组、before_right 组；未来原文在中间插入时可分别提出两侧候选。

## 4. 精确定位与连续顺序

GapAnchor 保存：根 composition_id、base_revision_id、parent_occurrence_path、left_occurrence_id、right_occurrence_id、affinity。

parent_occurrence_path 从根开始逐层定位子组合出现，不包含左右邻居本身。路径每一步必须是当前固定修订中的组合 occurrence。左右邻居必须是该父组合直接 nodes 中相邻的两项，不能用展平后的叶子编号代替。

- 根路径为空；文首 left=null，文末 right=null；两侧 null 仅在该父组合为空时合法。
- affinity 为 after_left 或 before_right，默认 after_left；只影响未来迁移建议，不改变当前间隙合法性。
- 同一子章节被嵌入两次，用完整路径区分；章节外前后间隙和章节内部间隙分别定位。
- 在两条个人内容之间插入，通过明确的前后 placement 邻居确定组内位置；服务器验证当前有序列表中的邻接关系，不使用浮点排序号。
- 普通移动可在组内重排或移至另一合法间隙；从来源组移除并加入目标组属于同一事务。空组从新修订移除，旧组历史保留。
- 两个不同 affinity 组交界处插入时，命令明确选择归属组；前端以后提供默认选择，不允许服务端猜测组归属。

读取递归输出章节边界、原文块和个人块。原文出现身份是完整 occurrence 路径，个人出现身份是 overlay_id + placement_id。去重块正文可以独立返回，阅读次序以输出项序列为准。

## 5. 保存与复用范围

建立个人层时指定可读的固定根组合及个人空间，一次事务建立空层修订、空个人层对应的阅读视图和请求收据。允许绑定可读工作修订，不要求它已经发布；后续原文发布不会自动改变基线。

保存入口以 request_id、expected_overlay_revision、expected_reading_view_revision 和明确操作为基础。支持插入既有块、原子创建正文并插入、修改正文并采用、移动、重排、移除一次出现及人工放置待放置内容。客户端不提交作者、时间或派生阅读顺序。

修改正文并采用时，显式列出要升级的 placement_id，全部必须指向被修改的稳定块。只更新这些出现处；同层未选择的位置、其它个人层和专题仍固定原修订。原子创建的个人正文落在个人层空间；修订已有块需有该块空间写权限，引用既有块只需读权限。

独立 ContentStore.revise 仍只修改块工作头；不会隐式扫描和更新所有阅读视图。用户已确认的自动生成阅读版本，应用于融合阅读保存入口。

每个成功且有效的操作生成一份层修订、一份视图修订及请求收据；正文操作额外产生块修订。纯结构操作不复制正文。无变化的新请求返回 Invalid(no_change)，不生成空修订；已成功请求原样重放优先返回原结果。

两种 expected 修订都必须匹配当前头；正文修订还检查其基础块头。失败返回冲突，不保留部分正文、placement、层、视图或幂等登记。未来前端负责保留未提交草稿。

## 6. 原文升级与迁移

迁移始终在同一稳定根内进行。先生成持久化提案，固定旧层修订和目标原文修订，不推进当前头。按旧组顺序计算每个组的建议，保存采用所需依据；affinity 不代表用户已授权迁移。

| 情形 | 提案结果 |
|---|---|
| 父路径仍解析到同一稳定父组合，两侧仍相邻 | exact；边界 null 必须仍是真实边界 |
| 原空父组合仍为空 | exact |
| 两侧都在但不相邻，或只剩一侧 | candidate；按 affinity 建议紧靠对应存活邻居的位置 |
| affinity 对应侧消失，但另一侧存在 | candidate；明确标明改靠另一侧，等待决定 |
| 路径失效、两侧消失、位置不唯一 | unresolved，进入待放置候选；不按正文相似度猜位置 |
| 两侧顺序反转 | unresolved，不把任一侧当作自动迁移依据 |

章节跨父移动、拆分与合并在本关保守判为 unresolved；B3 引入谱系后再扩展候选生成。B2 不为测试提前实现系统谱系。

提交迁移需要提案 ID 和当前层/视图预期头；固定提案的旧层必须仍是当前头。整次决定包括是否采用新基线，以及每组 exact / accept_candidate / manual / keep_unplaced 的处置。exact 也只有在整次迁移提交后生效并写记录。

拒绝整次迁移只追加拒绝决定，当前层和视图保持原值。采用新基线时，未安置组进入新层的待放置集合，正文引用、组内顺序和旧锚点继续保存。不能通过漏传组而删除内容：所有旧组必须恰好有一个处置。

多个旧组映射到同一新间隙且 affinity 相同时，提交必须显式给出合并后的 placement 顺序和组对应记录；若未提供则拒绝提交，不能按 UUID 随机排。跨组冲突不打乱任何原组内部相对顺序。

人工安置待放置组生成新的层/视图并追加决定记录。可选择合并到现有组并指定完整顺序。旧位置只作为历史依据，不能覆盖目标基线。

## 7. 权限投影与个人内容可找回

B1 的组合读取采用完整闭包授权。本关保留这一原文策略：原文固定闭包全部可读才输出原文结构和锚点。不可读或不存在时使用相同的 source_unavailable 状态，不返回基线 ID、路径、标题、隐藏数量或错误定位。

个人层读取先检查 owner 和个人空间，再独立检查各个人块修订的当前权限。可读个人内容继续返回；不可读个人块整项省略，不输出其 ID、占位、原顺序序号或隐藏数量。公开个人修订 DTO 不包含未经投影的原始锚点、迁移提案 JSON 或内容摘要，避免摘要成为隐藏信息旁路。

原文不可用时，可读个人内容统一进入待放置输出，定位为空；这是读取投影，不会写入一次永久迁移。原文权限恢复后，原保存位置仍可使用。待放置数量只统计实际返回的可读个人出现项。

写入普通已放置层时，要求所需原文闭包与所有层内个人引用可读，避免重写看不到的结构。原文失去权限后仍可单独读取/修订自己可写的块；重新编排原个人层需恢复原文权限或通过后续明确的脱离来源功能。本关不新增隐式脱离来源动作。

迁移历史读取对旧基线、目标基线分别授权：不可读一侧的锚点、原因细节和目标标识全部省略。层 owner 的决定状态可显示，但不能夹带隐藏原文信息。历史视图、请求重放同样使用当前授权；历史保存不赋予永久访问权。

## 8. 事务与存储约束

沿用 (actor_id, request_id) 全局请求键、规范化摘要及原 advisory lock 命名空间，新增 B2 操作种类。请求摘要保留有序 placement 和明确采用范围；同键改操作或内容返回幂等冲突。

写锁顺序：请求锁 → 按 UUID 排序的全部空间 grant → 个人层身份 → 阅读视图身份 → 按 UUID 排序的待修订块身份。读取和写入都使用固定引用；内部复用事务级块写入逻辑，不能调用自行提交的公共 ContentStore 后再保存个人层。

修改共享块的 P0-A 操作与 B2 操作遵守同样的授权锁先于块锁顺序；B1 不锁个人层，避免反向依赖。持久化提案与决定各自有请求收据；采用提案的层、视图、决定在同一事务。

新增 overlay、overlay_revision、gap_group/placement 修订明细、reading_view/revision、migration_proposal/decision 与类型化收据表。精确引用使用同对象复合 FK，组内位置唯一，placement 在同层修订中唯一；空 head 和跨 owner/根配对由约束及服务校验共同拒绝。

运行账号不能 UPDATE/DELETE 不可变修订、组明细、收据、提案和决定；仅更新身份表指定头指针。账号仍属于受信任服务，不引入用户级 RLS 声明。B2 没有搜索消费者；事务提交不表示后台索引已更新。

## 9. 预算与失败行为

继承 B1 每闭包 16 层、4,096 展开出现项、2,048 修订对象、8 MiB 去重 JSONB 正文预算。新增每层最多 512 个组、2,048 个个人 placement，单次正文创建/修订最多 32 块，个人可读正文单独限 8 MiB。两个正文预算独立：最坏总正文约 16 MiB，另有结构开销，不宣称是传输上限。

一个迁移提案最多处理该层的 512 组，只比较指定两个固定基线，不全库搜索候选。序列化输入限制和 JSON 字段严格校验将在施工单中落实；不接受未知动态引用或未实现的关系字段。

超预算直接返回固定错误，不返回部分融合结果；权限过滤发生在公开计数、顺序及摘要之前。原文 source_unavailable 与预算超限区分：后者不伪装成权限不足。

## 10. 验收与实施交接

1. 空根、文首文尾、嵌套空章节、重复子章节、个人块之间插入，逐项核对实际输出顺序和身份。
2. 同块两处只升级选定出现，独立改块不漂移旧视图；移动只改结构，移除出现不删除块。
3. 同基础并发一成一冲突，含不同间隙竞争；插入正文后注入视图/收据写失败，所有结构、正文、头和请求登记全部回滚。
4. 精确迁移、插入新邻居、单侧消失、空章节变化、邻居逆序、父路径失效、重复章节、拆分/跨章节移动，以及多个组碰撞均有确定结果。
5. 拒绝提案保持旧头；采用新基线但留待放置、后续人工安置均保留旧视图和决定；过时提案不能覆盖新编辑。
6. 撤销原文或个人块权限，验证正文、锚点、错误、计数、顺序、摘要和迁移记录不泄露；自己可读的个人正文仍可找回，原文权限不能获得个人层。
7. 幂等重放、跨操作键冲突、真实授权锁等待、普通运行角色约束；空库安装与已有 B1 数据升级分别验证，保留原 68 项回归。
8. 固定源码包在隔离 Linux 宿主与全新 Compose 验证，核对哈希、命令、退出码与停止状态；实施末尾一次独立代码审查。
