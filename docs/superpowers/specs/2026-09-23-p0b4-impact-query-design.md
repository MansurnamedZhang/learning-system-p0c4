# P0-B4 查询与修订影响设计

2026-09-23 · VERIFIED / NOT_PRODUCTION · 基于已验收的 B3 `4252cc8` 和 P0-B 总施工单 §6；B4 最终提交 `fc25e91954419bd0c6c272d00577db1b74ce6ce8`

## 目标与边界

给一个**精确修订**回答三类问题：谁直接引用它；附近有哪些明确保存的证据与关系；如果此修订变化，哪些固定阅读、文档或判断需要人工复查。结果解释每一条可见路径，分别保留去重消费者和所有 occurrence／placement 位置。PostgreSQL 仍是权威库。B4 不改变任何历史事实，不计算真假、不自动迁移阅读或发布，也不扩入 HTTP、网页和学习任务。

查询是当前授权下的只读投影。在投影事实、计数、游标和 `BudgetExceeded` 状态上，当前看不到的对象与不存在的对象一致；隐藏中间节点不能接通两段可见路径。基础设施超时/不可用统一为通用存储错误，既不返回内部密度，也不承诺两种数据库负载下可用性与响应时间完全相同。候选行、原始 JSONB、内部总数和过滤数量都不能作为公共返回值。旧快照固定当时的选择，新的查询仍重新检查现在的权限。

## 查询契约

请求具有 `start: ImpactStart`、`scope`、可选的非空 `families`（省略时仅结构与必要引用）、`max_depth`、`limit`、`work_limit` 和可选 `after`。`ImpactStart` 包含 B3 `ExactRef` 的精确对象，并额外支持精确 `CompositionRef`；不为此扩大 B3 的引用对象注册域。`scope` 为二选一：`Reading { view: ReadingRef, mode: ReadingMode }` 或 `Release { release_id }`。`start` 的对象身份与修订必须同时匹配；H@1 与 H@2 不合并。读取固定 view/release，不替换为当前 head。起点必须属于下述精确范围成员；不属于、不可访问或不存在的 scope/start 使用相同的 `None` 结果。

单次响应使用一个 `READ ONLY REPEATABLE READ` 事务。先解析 scope 和 start，再发现候选、逐项授权、构造可见路径，最后排序与截取。`Reading` 按 B3 `read_versioned` 的同一模式投影决定显示成员：`Original` 只有可见原文块及其 occurrence；`Personal` 只有可见个人块/placement；`Fused` 有两类。`Personal/Fused` 的 `unplaced` 是可见个人成员，但只给无有效位置的标识，不伪造原文路径。固定选择的可见关系/审查，以及上述成员完整必要闭包里的精确对象也可作为起点，但标为 `Selected/Context`，不因成员资格就变成一次显示或直接引述。若原文来源已撤权，沿用 B3 的 `SourceProjection::Unavailable`，仍可查询可见个人成员；原文组合和原文块不属于本次范围。`Release` 必须先通过 B3 的完整清单授权；manifest 的精确对象/组合可作为 `Context` 起点，实际显示/直接引用仍仅由固定根、阅读视图和真实边证明。工作态动态关系只纳入当前可读且至少一端是显示块的关系，标注为动态发现；另一端若不属于范围成员，只能作为可读外部端点显示并停止扩展。发布态只使用发布时固定的关系与证据清单。任何关系另一端只有当前可读且属于范围成员时才可走向下一跳。

允许的边族是 `Structural`（组合 occurrence、个人 placement、固定阅读与发布包含）、`Necessary`（已登记的正文依据/目标/上下文、关系与审查的必要依赖）、`Semantic`（显式用户关系，保留类型和方向）、`ReviewSelection`（固定关系／审查选择）和 `Lineage`（系统派生、拆分、合并来源）。影响反向查询从**任一精确端点**找到触及该版本的关系修订，例如 B 改动必须发现原有 `A supports B`；解释仍保留 `A → B` 保存方向。显式语义遍历可经关系到可见且在范围内的另一端，标明遍历是顺向或逆向，环由路径预算截断；这只表示建议复查，不将支持、反对或真假传递。语义关系只生成“建议复查”解释，结构引用生成“引用此旧版，采用新版需明确生成新组合”。`related_to` 保存为规范端点顺序但查询可从任一端进入；其他关系同样可从任一端发现受影响的断言，说明中始终携带其原有方向与类型。来源谱系不推断事实支持的传递性。默认边族只启用结构与必要引用，语义、选择和谱系需请求显式列入。

消费者是带类型的精确对象（块修订、组合修订、阅读视图、关系修订、人工审查、谱系操作或发布），同一个消费者只计一次；`locations` 单独列出每条可见 occurrence UUID 路径或 placement ID。关系消费者可以没有结构位置。两条路径到同一消费者保留两条 `explanations`，不能用消费者去重删除位置或理由。发布清单的递归成员关系不是一次新的直接引述；直接引用由实际 occurrence、placement、依赖或显式选择建立。

结果包含解析后的固定 `actual_scope`、可见消费者与解释路径、`Complete | Truncated { after } | BudgetExceeded`。**分页原子单位是消费者组**：同一消费者的所有可见路径和位置必须同页返回；`limit` 数消费者，游标是最后一个可见消费者的稳定排序键。若单个组越过路径/字节预算，整次查询为 `BudgetExceeded` 而不返回半组。无结果且 `Complete` 才表示本范围内没有可见影响。`Truncated` 仅因 `limit` 而发生；下一页重新授权并重算，权限或工作态关系变化可改变页成员，不保证跨变化的静态快照。工作预算用尽时返回 `BudgetExceeded`，不返回部分路径、内部数量或隐藏身份。游标不保存授权。

服务端上限：深度 8、返回消费者 200、**可见**图边检查 8192、不同可见节点 2048、解释路径 4096、投影载荷 8 MiB、可见工作步骤 131072。请求可选择更小上限，默认深度 3、返回 50、可见工作 4096。隐藏候选不计入公开工作预算；在 SQL 用当前 grant/overlay 所有权预过滤，随后逐项完整授权，只对可见图计数。隐藏候选再多也不能单独触发公开 `BudgetExceeded` 或改变可见分页/总数。反向访问须使用目标优先索引和有界 keyset 批次，不能先 `fetch_all` 全图后截断；每种查询在稠密且大量未授权夹具上实测 `EXPLAIN (ANALYZE, BUFFERS)`。15 秒只读语句超时或内部扫描防护失败是通用存储不可用，绝不伪装成 `Complete`、零影响或可见预算超限。必要依赖的 B3 授权闭包预算仍单独生效；若单个可见对象的完整授权也超限，整次查询失败且不返回部分路径。

排序先取每个消费者的最短可见解释路径，按该路径的跳数、边族与路径键，再按消费者类型与精确身份定组序；组内路径与完整 occurrence/placement 路径另行稳定排序。授权、范围过滤与路径完整性先于总数和游标。首版不返回未经完整可见扫描确认的总数；`Complete` 时可返回去重消费者数，`Truncated` 和 `BudgetExceeded` 不返回推测总数。

## Task 3 局部证据契约补充

局部证据使用独立的 `EvidenceQuery`／`EvidenceResult`：请求给出精确 `BlockRef` 端点、上述固定 `scope`、是否纳入动态工作态、返回数／可见工作预算及可见游标。独立契约用于携带经授权的关系断言原文（保存的方向、类型、条件、理由）和审查投影；不把这些字段硬塞入只表示图边的 `ImpactStep`。端点必须是当前可读的精确范围成员；固定选择由当时阅读视图的选择行及其关系—审查配对取得，历史 release 只取发布时冻结的阅读选择，manifest 的 Context 成员不能冒充选择。

动态工作态需要请求明确开启，仅支持 Reading scope 中实际显示的端点；Release scope 不接受动态模式。它仅发现触及该精确端点的当前关系 head，并标注 `DynamicWorking`，不会替换、修改或删除固定选择。该 head 对应的最新关系审查若为 `Withdrawn`，动态发现略过它；固定历史选择及其当时选定审查仍按原修订投影。一个精确关系修订同时来自固定与动态来源时合成一个原子断言组，保留多个来源；不同关系修订绝不合并。固定选择的认识审查只在其目标精确端点匹配时投影。审查若根可见但必要依据不全，只给无身份、无状态及无隐藏计数的 `Incomplete`；审查根不可见则省略该审查投影，关系本身仍按其独立授权判断。另一端可读但不在范围内时可展示精确端点，不能沿其继续扩展。局部查询不推断证据独立性或命题真假，沿用单快照、先授权后计数及可见组原子分页的预算规则。

匿名认识审查的路由也先走授权：先确认查询端点为当前可读的范围成员，再从固定选择读取内部候选；对审查根先检查直接可见性，不可见即忽略。只有根直接可见时，才在同一快照内部比较其精确 target 与已授权端点；完整依赖授权失败只返回该端点的一枚匿名 `Incomplete`，其 ID 或哈希不得进入公开排序键、游标或计数。发布含多个固定阅读时，同一关系修订仍只是一组，但每个来源分别保留其阅读视图、所选审查及投影，不混成一个全局审查。

同一精确认识审查修订若被多个固定阅读视图选中，也只形成一个审查组；组内列出每个当前可见的固定阅读来源，游标以审查本身的精确身份排序，不以来源视图把它拆成多个消费者或页面。匿名 `Incomplete` 仍只是一枚端点级标记，不附来源。

## 存储与执行

复用 `reference_dependency_target`、`occurrence_block_target`、`occurrence_composition_target`；只追加针对真实执行计划有用的目标优先索引，旧 0001–0006、根 Cargo.lock、v1 摘要与 B3 冻结源码不改。新索引不能成为第二套权威关系；查询从现有不可变行与固定 view/release 导出。读取 `reference_dependency` 与 `system_lineage` 必须经 B3 `Session` 和对应对象授权投影，绝不直接返回原始行。每条可扩展路径在扩展前校验当前节点与完整必要闭包，未授权节点立即截断该路径。

对组合按根到叶逐 occurrence 遍历，路径由 UUID 序列而非仅块身份组成；相同子组合在两个位置出现时保留两条路径。个人块使用固定阅读视图的 placement 身份和位置，待放置项不冒充有效原文位置。证据局部查询仅返回可读关系／审查；审查依据不完整时沿用不含身份的 `Incomplete`，不能沿其隐藏依据继续扩展。
