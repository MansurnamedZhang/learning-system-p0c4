2026-09-23 · P0-C 实施设计 · 起点基线 `fc25e91954419bd0c6c272d00577db1b74ce6ce8` (`P0_B4_VERIFIED / NOT_PRODUCTION`)

## 目标和阶段边界

P0-C 要让现有不可变块、组合、个人位置、关系与审查能够携带真实原件，并在后台故障及干净实例恢复后仍可核对。交付分 C1 原件与附件、C2 持久任务、C3 融合快照交换、C4 完整备份恢复四关；每关有独立行为测试和证据，C4 通过才标记 P0-C 完成。P1-A 才加入登录、HTTP 和网页编辑；P1-B 才加入学习任务、尝试、产物和验收事实，并补验这些事实的备份闭包。P0-C 不将现有课程库批量导入、OCR 质量、全文搜索、S3 兼容性或生产上线作为验收替身。

在 P0-C 设计起点，Rust workspace 只有 `learning-core` 与 `learning-db`。当时 `ContentDraft` v1 为文本，v2 的 `BodyV2` 为文本、块引用、关系视图，尚无 v3 图片/附件。`outbox_event` 在发布事务中写入，但限定 `composition_released`，没有作业领取/完成语义。随后 C1 追加 v3 和资产能力，C2 追加独立 `job_outbox`/`job` 协议；旧迁移、v1/v2 摘要、旧收据及固定历史保持不变。

## 选型

| 方案 | 优点 | 代价和结论 |
|---|---|---|
| 全部字节放 PostgreSQL | 单库事务简单 | 大原件、备份及范围读取负担随资料增大；不采用 |
| PostgreSQL 元数据 + 本地不可变文件卷 | 符合单机 Compose 与现有设计；原字节、数据库事务各有清晰边界 | 需写入协议和闭包备份；**首版采用** |
| PostgreSQL 元数据 + S3 后端 | 便于跨主机对象存储 | 增加外部服务与兼容性验证；只保留适配接口，首版不承诺实现 |

PostgreSQL 是身份、修订、权限、位置、关系、作业状态的唯一权威。文件接口只保存不可变字节，不从文件名生成业务身份；`asset_id`、来源资源版本和 SHA-256 分别表示业务对象、来源修订和物理内容。文件存储键由服务端生成。派生预览可重建，不冒充原件。

## C1：原件、图片与附件

- `Asset` 记录空间、资产 ID、原始大小、SHA-256、经校验的媒体类型/文件名与就绪状态；原始字节在 `assets/sha256/<前缀>/<摘要>`。同一私有库内相同字节可复用物理对象，但两个资源或两个图片位置不因此变成一个业务身份。首关要求块修订与其资产记录同属一个空间；跨空间复用字节时另建目标空间内的逻辑资产记录。下载只能通过已授权的精确 `AssetUse`（资源版本或块修订），不能仅凭哈希或资产 ID 枚举。
- `Resource` 与不可变 `ResourceVersion` 固定来源、原件资产及版本。来源定位引用精确资源版本与页/区域、代码位置、Notebook cell 或时间范围；不能以临时 URL 或新分页替换旧定位。首关用 PDF、图片和 Notebook 各一个原件验证字节与定位字段，不要求解析出知识块。
- 为图片和通用附件新增 `ContentDraft` v3，而不是修改 v1/v2 序列化。图片体含精确 `AssetRef`、用途、图注以及替代文本或显式装饰标志；附件体含精确 `AssetRef` 和展示名。移动图片只变更 occurrence/placement，替换图片产生新资产和块修订。v3 与旧修订可同处组合及融合阅读。
- v3 沿用现有块级必要引用语义，资产引用另存精确 `block_asset_use`；旧 `ReleaseStore::publish` 的 v1 发布契约继续拒绝任何结构化 v2/v3 块，包含 v3 的发布走现有证据清单发布路径。旧阅读、关系、审查和影响查询遇到 v3 须正确投影或明确拒绝，不能因新增枚举分支改变 v1/v2 行为。
- 上传按 `upload_id` 流式写 staging、边写边计数/计算 SHA-256、核对字节和声明限制；staging 与 assets 为独立卷时，先复制并核验到 assets 卷内的临时路径，再在 assets 卷内原子定稿，不能跨卷重命名。只有定稿字节再次可读且校验后，数据库事务才能登记就绪资产及其精确引用。重复相同请求返回同一收据；相同键不同内容冲突。定稿成功而数据库回滚留下的无引用对象延迟对账；C1 只报告候选，不自动删除。真正清理须在 C4 的备份保护集合可用后另行验证，并排除活动上传和所有权威引用。
- 授权沿用当前 space grant 和个人层归属。读取资产必须先核验引用它的精确资源/块当前可见，再由受控接口打开字节；隐藏对象与不存在对象采用同一外部行为。外部输入不得决定最终文件路径。资产损坏或缺失返回明确不可用，不能展示假“已就绪”图片。

## C2：持久后台任务

既有 `outbox_event` 的 `aggregate_id` 外键固定指向 `release`，因此保持原表、原事件及旧升级夹具；新增通用 `job_outbox` 与 `job`，以有记录的 outbox→job 转投协议处理资产等新事件，不把一次发布事件直接当作可重试作业。业务事务写入相应 outbox；Worker 在普通非 owner、非 BYPASSRLS 身份下原子领取任务，使用租约令牌与到期时间防止旧 Worker 在租约易主后提交。作业记录输入精确修订、处理器版本、幂等键、尝试次数、状态、错误类、输出摘要与可选分段检查点。状态为 `queued/running/retry_wait/succeeded/failed/cancelled`；重试是至少一次执行，**副作用按幂等键收敛**，不承诺进程只执行一次。

首个真实处理器为资产完整性/轻量元信息检查；预览可作为第二处理器。解析失败保留正确登记的原件；发布成功而预览失败不撤销正文。验收必须真实终止领取后的 Worker，等待租约过期并由另一进程完成，同时检查重复消费、取消与旧令牌提交被拒绝。

## C3：融合快照交换

输入为精确 `ReadingViewRevision`、显示模式和是否携带原件；输出固定版本化 manifest、逐修订 JSON、位置/关系/审查记录、必要资产和校验报告。先在一个只读一致快照中按**当前授权**求闭包与精确对象清单，再复制不可变资产。导出作业完成前与交付文件时重验访问权；撤权后服务器不得继续提供暂存包。已下载到用户设备的旧文件不在服务器撤权能力范围内。

包格式明确区分融合快照、个人完整备份和模板包：模板默认没有个人层；融合快照只含所选范围及显式选择的个人数据；缺少授权的引用给明确未包含标记，绝不偷带私有正文、隐藏 ID、关系路径或计数。HTML/Markdown 是阅读副本，版本化 JSON 才是无损交换权威。导入先检格式版本、对象身份/摘要、资产 SHA、引用闭包、权限归属和路径安全，在 staging 通过后一次性发布可见批次；同 ID/修订同字节幂等复用，不同字节拒绝，不留下半可用视图。

## C4：完整备份与干净实例恢复

备份和授权导出使用相同的资产哈希/引用校验工具，但备份范围是全部权威数据。首版采用短写入维护窗：阻止新发布、个人保存、上传定稿和 Worker 业务写入，等在途事务收束，取得一致 PostgreSQL 备份与对应完整资产清单，保护清单资产后恢复写入，复制并校验到另一故障域。只有数据库、清单、全部权威资产及所需模式/角色重建信息齐全才标记 `complete`；密钥另存，派生缓存不进入权威闭包。

恢复只在干净实例进行：预检摘要与兼容性，建立角色/模式，恢复数据库和资产，重置失效任务租约，重建派生物并核对固定旧版、当前版、个人间隙、待放置记录、关系/审查和权限。缺文件、摘要不符或引用不闭合时停止，不能把部分实例标记可用。P0-C 验现有内容闭包；P1-B 完成后另补学习事实闭包。

## 代码责任与迁移顺序

1. `learning-core` 增加 v3 内容和资产/来源/包契约；旧 v1/v2 解码、摘要与关系语义不变。
2. `learning-db` 以 0009 起追加资产/来源和授权表，再追加作业、导出/导入/备份运行记录；每个迁移保留旧版本冻结程序升级路径。直接数据库权限与服务层授权均有负面测试。
3. 独立文件存储适配模块只处理原字节与暂存；数据库写入服务编排“字节先就绪、引用后提交”。Worker 与可移植性模块复用核心类型与数据库授权，不形成另一套 JSON 权威正文。
4. Compose 验收用独立数据库、资产卷、staging 卷和隔离作业；不接触既有测试卷、课程原件或生产服务。每关保存提交、源码包/镜像摘要、迁移、命令、退出码、原始日志和限制。

## 验收夹具与失败语义

固定 Attention 样例：一份原格式讲义和一张图片、H@1/H@2、两份复用同块的组合、个人插入图片与笔记、E1/E2/X 关系、固定 Reading/Release、一次拆分及待放置记录。C1 验文件原字节和图片位置；C2 验中断恢复；C3 验授权闭包的包往返；C4 验全量干净恢复。每关继续运行 B4 旧 284 项的真实回归、四类冻结旧程序升级、格式与严格 Clippy；计数以实际源码和日志为准，不预写为通过。

必须保留的失败注入：上传中断；文件定稿后数据库回滚；已登记资产被损坏；同请求键不同字节；撤权后资产/导出访问；Worker 旧租约迟到；导出缺隐私目标、缺资产或被篡改；导入同 ID 不同正文；备份复制中断与恢复缺文件。失败不得产生伪就绪资产、重复副作用、半可见导入或标为 `complete` 的残缺备份。
