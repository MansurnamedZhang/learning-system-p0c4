# P0-C2 实现边界

C2 在 C1 的不可变原件与精确块资产使用关系上追加持久后台任务。v3 Figure/Attachment 的真实写入在同一业务事务中写 job_outbox；旧请求收据重放不新增事件。旧 release outbox_event 保持独立，转投器以稳定业务键将新事件原子收敛为一条 job。仅登记资产、尚未形成精确块使用，或只关联资源版本时，本首个事件不会自动入队。

Job 以数据库时钟和数据库生成的租约 token 原子领取；当前 token 才能续租、写检查点、完成或失败。到期接管增加 attempt，最多三次尝试，失败按有界类别与退避处理。它保证至少一次执行和副作用收敛，不承诺进程只运行一次。取消与终态不可复活。Worker 以普通非 owner、非 BYPASSRLS 的 learning_runtime 身份连接；资产处理器依原业务 actor 和精确 BlockRef 重新检查当前授权，再核对原字节大小/SHA-256，最后通过带 token 条件的单事务函数写版本化结果。

该 runtime 是可信内部服务身份，不构成每个 Worker 或每个最终用户独立的数据库权限域。持有它和当前 token 的其他内部代码仍可误用通用 succeed 函数，令资产任务 succeeded 却无专用结果；直接调用专用完成函数也可绕过 Rust 的字节复核。这些是后续收紧的 P2 契约边界。专用容器验收把 Worker 文件系统限制为 runtime secret、只读资产和二进制，无法证明宿主 root 或 Docker daemon 无法读进程环境中的 runtime DSN。

首个处理器只做资产完整性和轻量元信息；上传声明限额、有限媒体签名/形状检查仍属于 C1。损坏或缺失资产使任务失败或重试，但已正确登记的原件与正文不回滚。预览、OCR、完整 PDF/图片解析、恶意文件扫描、资源版本事件、C3/C4 和生产部署均在本边界之外。

独立验收及证据见 [C2 验证记录](p0c2-verification.md)。生产前还需单独修复 Linux 服务器 UTC 时钟偏差并验证时间同步。
